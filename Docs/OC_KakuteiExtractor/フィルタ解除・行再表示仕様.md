## 2. 目的

`学生情報一覧`の通常フィルタ本体を残したまま絞り込み条件だけを解除し、利用者が手動で非表示にした行を再表示する。

行グループは通常の行非表示とは別機能として扱い、本ツールでは展開も折りたたみも行わない。抽出処理は行グループの開閉状態や行の表示状態に依存せず、検証済みのシートデータ全体から対象行を取得する。

## 3. 変更理由

旧版は次の処理を行っていた。

```javascript
sourceSheet.expandRowGroupsUpToDepth(8);
```

利用者環境ではこの呼び出しにより、次のエラーが発生した。

```text
行グループを展開できませんでした。
```

Google Apps Scriptの行グループ展開APIは、シート上のグループ有無やシート状態によって例外となり得る。行グループ展開は元の必須要件ではなく、抽出結果の完全性にも不要であるため、処理経路から削除する。

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 通常フィルタ本体 | シート上のフィルタボタンとフィルタ対象範囲 |
| 絞り込み条件 | 各列に設定された値、条件、色などのフィルタ条件 |
| 保存済みフィルタ表示 | Google スプレッドシートの「フィルタ表示」。通常フィルタとは別機能 |
| 手動非表示行 | 利用者が行メニューなどから非表示にした行 |
| 行グループ | アウトライン機能で折りたたみ・展開する行群 |

## 5. 確定仕様

### 5.1 通常フィルタ

- 通常フィルタ本体を削除しない。
- `Filter.remove()`を使用しない。
- 各列の絞り込み条件だけを`removeColumnFilterCriteria()`で解除する。
- フィルタ範囲、フィルタボタン、列順、行順を維持する。
- 条件解除前に既存条件をコピーして退避する。
- 条件解除に失敗した場合は、可能な限り元の条件へ復元する。
- 保存済みフィルタ表示を削除・変更しない。

### 5.2 手動非表示行

- `showRows(1, getMaxRows())`でシート上の全行を再表示する。
- 行再表示後に`SpreadsheetApp.flush()`を実行し、遅延エラーを確定する。
- 行再表示に失敗した場合は、フィルタ条件へ触れずに中止する。

### 5.3 行グループ

- `expandRowGroupsUpToDepth()`を使用しない。
- `expandAllRowGroups()`を使用しない。
- `collapseAllRowGroups()`を使用しない。
- 行グループの開閉状態を変更しない。
- 行グループが折りたたまれていても、抽出対象から除外しない。

### 5.4 列の表示状態

- 非表示列を再表示しない。
- 列グループを展開・折りたたみしない。
- コピー対象列は列の表示状態にかかわらず取得する。

## 6. 実行順序

表示変更は次の順序で行う。

1. 通常フィルタと条件を読み取り専用で退避する。
2. シート保護を事前確認する。
3. 手動非表示行を再表示する。
4. `SpreadsheetApp.flush()`で行再表示の成否を確定する。
5. 通常フィルタの各列の絞り込み条件だけを解除する。
6. `SpreadsheetApp.flush()`で条件解除を確定する。
7. コピー確認画面へ進む。

行グループAPIはこの処理順序に含めない。

## 7. フィルタ条件の退避

通常フィルタが存在する場合、フィルタ範囲内の各絶対列番号について`getColumnFilterCriteria()`を呼び出す。

条件が設定されている列は、次を保持する。

- シート上の絶対列番号
- `FilterCriteria.copy().build()`で複製した条件

通常フィルタが存在しない場合は、フィルタ関連処理を省略し、手動非表示行の再表示だけを行う。

## 8. 失敗時の安全動作

### 8.1 保護状態を確認できない、または編集できない

行やフィルタ条件へ触れる前に中止する。

```text
フィルタ本体、絞り込み条件、行の表示状態は変更していません。
```

### 8.2 手動非表示行の再表示に失敗

- フィルタ本体を変更しない。
- フィルタ条件を変更しない。
- 行グループを変更しない。
- コピー確認画面へ進まない。

利用者向けメッセージには、行グループの開閉状態も変更していないことを明記する。

### 8.3 フィルタ条件解除に失敗

退避した全条件を`setColumnFilterCriteria()`で復元し、`SpreadsheetApp.flush()`を実行する。

復元に成功した場合は、元の条件へ戻したことを通知する。復元にも失敗した場合は、フィルタ本体は削除していないことと、一部条件が戻っていない可能性を通知する。

いずれの場合も行グループの開閉状態は変更しない。

## 9. 抽出結果との関係

本ツールは、フィルタや非表示状態を参照して抽出対象を決めない。

対象行は次の情報から決定する。

- 検出したヘッダー行より下にあること
- `学籍番号`が存在すること
- 必須列と対象日付列の検証に合格すること

したがって、行グループが折りたたまれていても、該当学生は抽出・並べ替え・TSV生成の対象になる。

## 10. 既に削除されたフィルタの復旧

過去の旧版によって通常フィルタが削除された場合、削除前の範囲と条件をツールから完全自動復元することはできない。

1. `学生情報一覧`を開く。
2. ヘッダー行からデータ最終行・最終列までを選択する。
3. `データ`→`フィルタを作成`を実行する。
4. 必要な条件を手動で再設定する。
5. 保存済みフィルタ表示が残っている場合は参考にする。

## 11. テスト要件

- 通常フィルタ本体の`remove()`が呼ばれない。
- 条件が設定された列だけを解除する。
- A列以外から始まるフィルタ範囲でも絶対列番号を使用する。
- 通常フィルタがなくても手動非表示行を再表示する。
- シート保護時は無変更で中止する。
- 行再表示失敗時は条件を変更しない。
- 条件解除失敗時は全条件を復元する。
- 行グループ展開・折りたたみAPIを一度も呼ばない。
- 行グループAPIのモックが例外を投げる構成でも正常処理できる。
- 確認画面に行グループを変更しないことを表示する。

## 12. 受け入れ基準

1. 実行後も通常フィルタのボタンと範囲が残る。
2. 各列の絞り込み条件だけが解除される。
3. 手動非表示行が再表示される。
4. 行グループの開閉状態が変化しない。
5. 行グループが存在しないシートでもエラーにならない。
6. 行グループが折りたたまれていても対象データが抽出される。
7. 行再表示に失敗した場合、通常フィルタと条件が変更されない。
8. 保存済みフィルタ表示、列表示、セル値、書式、行順を変更しない。
