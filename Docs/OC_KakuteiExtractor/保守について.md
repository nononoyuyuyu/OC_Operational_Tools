# OC_KakuteiExtractor 保守について

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |
| 対象ツール | `OC_KakuteiExtractor` |
| 版 | 1.8 |
| 最終更新日 | 2026年9月4日 |

## 2. 最重要の不変条件

1. 通常フィルタ本体を削除しない。
2. `Filter.remove()`を実装へ再導入しない。
3. 手動非表示行の再表示を確定してから、フィルタ条件だけを解除する。
4. 条件解除失敗時は退避した条件を復元する。
5. 行グループを展開・折りたたみしない。
6. 保存済みフィルタ表示を変更しない。
7. 元シートのセル値、書式、行順、列順を変更しない。

## 3. 表示初期化の構成

| 関数 | 責務 |
| --- | --- |
| `ocKakuteiResetSourceSheetView_` | 全体の順序制御 |
| `ocKakuteiCaptureStandardFilterState_` | 通常フィルタと条件の退避 |
| `ocKakuteiAssertViewResetPermission_` | シート保護の事前確認 |
| `ocKakuteiRevealManualHiddenRowsSafely_` | 手動非表示行の再表示 |
| `ocKakuteiClearStandardFilterCriteriaSafely_` | 条件だけを解除し、失敗時に復元 |
| `ocKakuteiRestoreStandardFilterCriteria_` | 退避条件の再設定 |

旧関数`ocKakuteiRevealAllRowsSafely_`は廃止した。

## 4. フィルタ条件の扱い

フィルタ範囲の開始列と列数を取得し、絶対列番号で条件を走査する。

```javascript
var firstColumn = filterRange.getColumn();
var columnCount = filterRange.getNumColumns();
```

条件がある列だけを退避する。

```javascript
var columnCriteria = filter.getColumnFilterCriteria(columnPosition);
var copiedCriteria = columnCriteria.copy().build();
```

解除時は次だけを使用する。

```javascript
filter.removeColumnFilterCriteria(columnPosition);
```

次は禁止する。

```javascript
filter.remove();
```

## 5. 変更順序

順序を変更してはならない。

```text
条件退避
→ 保護確認
→ showRows
→ flush
→ removeColumnFilterCriteria
→ flush
```

行表示前に条件を解除すると、後続の権限エラーで条件だけが変更された中途半端な状態になる。

## 6. 行グループの取扱い

本ツールでは行グループAPIを使用しない。

禁止する呼び出し:

```javascript
sourceSheet.expandRowGroupsUpToDepth(...);
sourceSheet.expandAllRowGroups();
sourceSheet.collapseAllRowGroups();
```

理由:

- 行グループが存在しないシート等で展開APIが例外となり、抽出が中断した実績がある。
- 行グループ展開は元の必須要件ではない。
- 抽出処理は行の表示状態に依存せず、折りたたまれた行も配列から取得できる。
- 不要な画面状態変更を避けられる。

行グループの開閉状態は実行前後で同一に保つ。

## 7. 失敗時の処理

- 保護確認失敗: 無変更で中止
- 手動非表示行の再表示失敗: フィルタ条件へ触れず中止
- 条件解除失敗: 退避した全条件を復元
- 条件復元失敗: フィルタ本体を保持したまま、不完全復元の可能性を通知

行グループはどの失敗経路でも変更しない。

元例外へ学生情報を付加したり、`Logger`や`console`へ出力したりしない。

## 8. テスト

```bash
node Tests/OC_KakuteiExtractor/logic.test.js
node Tests/OC_KakuteiExtractor/workflow.test.js
node Tests/OC_KakuteiExtractor/view-reset.test.js
node Tests/OC_KakuteiExtractor/static.test.js
```

必須の表示状態回帰試験:

- フィルタ本体の`remove()`が呼ばれない
- 条件だけが解除される
- A列以外から始まるフィルタ範囲
- シート保護時の無変更
- `showRows()`失敗時の無変更
- 行グループAPIが一度も呼ばれない
- 行グループAPIのモックが例外を投げる構成でも処理が成功する
- 条件解除途中失敗時の復元
- 復元失敗時の警告
- 通常フィルタなし

## 9. 実機試験

- フィルタボタンと範囲が実行後も残る
- 複数列の条件が解除される
- 色フィルタ、値フィルタ、条件フィルタを退避・復元できる
- 保護されたシートで無変更中止する
- 手動非表示行が再表示される
- 行グループの開閉状態が変化しない
- 行グループが存在しないシートでエラーにならない
- 折りたたまれた行グループ内の学生もコピー対象になる
- 保存済みフィルタ表示が変化しない

## 10. 更新手順

1. 最新`main`から修正ブランチを作成する。
2. 実装、テスト、設計書、利用資料、保守資料を同じPRで更新する。
3. コミットとPRを日本語で記載する。
4. 実機受け入れ試験前はPRをDraftとする。
