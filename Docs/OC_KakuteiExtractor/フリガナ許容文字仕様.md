## 2. 目的

留学生を含む学生情報では、フリガナ欄に半角カタカナだけでなく、ローマ字、数字、ハイフン、アポストロフィ、ピリオド、スラッシュ、丸括弧などが使用される。

本仕様は、実際の氏名表記を不必要に拒否せず、TSVの構造を壊す文字や、貼り付け先で式・特殊入力として解釈され得る不要な記号を許可しないためのホワイトリストを定める。

## 3. 必須性

`フリガナ`は各学生行で必須である。

- 空文字は許可しない。
- 半角スペースだけの値は許可しない。
- 許容文字で構成された1文字以上の値を必要とする。

## 4. 許容文字

### 4.1 半角カタカナ等

次のUnicode範囲を許容する。

| Unicode範囲 | 内容 |
| --- | --- |
| `U+FF61`～`U+FF9F` | 半角句読点、半角カタカナ、半角濁点・半濁点 |

半角長音記号`ｰ`は`U+FF70`であり、この範囲に含まれる。

### 4.2 ASCII文字

次を許容する。

| 種類 | 許容文字 |
| --- | --- |
| 半角英字 | `A-Z`、`a-z` |
| 半角数字 | `0-9` |
| 空白 | 半角スペース`U+0020` |
| 氏名用記号 | `-`、`'`、`.`、`/`、`(`、`)`、`&`、`_`、`,` |

実装上の判定式は次のとおりである。

```javascript
/^[A-Za-z0-9 .,'()\/&_\-\uFF61-\uFF9F]+$/
```

ASCIIの表示可能文字全体を許可するのではなく、氏名表記で使用する文字だけを明示的に許可する。

## 5. 許容例

```text
ｻﾄｳ ﾀﾛｳ
ﾏﾘｱ-ｶﾞﾙｼｱ
ｽｰ･ﾘｰ
LEE-JUN HO
O'NEIL
SMITH.JR
AN/LEE
ﾁｬﾝ(LEE)
LAST, FIRST
A&B_C
STUDENT-2
```

## 6. 許容しない例

### 6.1 全角文字等

| 値 | 理由 |
| --- | --- |
| `サトウ タロウ` | 全角カタカナを含む |
| `さとう` | ひらがなを含む |
| `ﾁｬﾝ－ﾘｰ` | 全角ハイフン`U+FF0D`を含む |
| `ＬＥＥ` | 全角英字を含む |
| `LEE　JUN` | 全角スペースを含む |
| 改行・タブ・復帰文字を含む値 | TSVの行・列構造を壊す |

### 6.2 ホワイトリスト外のASCII記号

次の記号は許可しない。

```text
= + @ < > # : ; ` | \ { } [ ]
```

例:

```text
=IMPORTXML("...")
+SUM(1,2)
@CMD
A<B
A>B
A#B
```

これらは通常の氏名表記に不要であり、特に`=`、`+`、`@`などは、コピー先の表計算ソフトで式または特殊な入力として解釈される可能性があるため、許可しない。

## 7. ハイフンと長音記号

見た目が似ている文字を区別する。

| 文字 | Unicode | 判定 |
| --- | --- | --- |
| `-` | `U+002D` | 許可 |
| `－` | `U+FF0D` | 不許可 |
| `‐` | `U+2010` | 不許可 |
| `–` | `U+2013` | 不許可 |
| `—` | `U+2014` | 不許可 |
| `ｰ` | `U+FF70` | 許可 |
| `ー` | `U+30FC` | 不許可 |

利用者がASCIIハイフンを使用しているつもりでも、入力元からのコピーにより全角ハイフンやダッシュへ置き換わることがある。エラーのUnicodeコードポイントで確認する。

## 8. 正規化方針

フリガナの出力値は、シート上の表示文字列をそのまま使用する。

- 全角カタカナを半角へ自動変換しない。
- 全角英数字や全角記号を半角へ自動変換しない。
- ハイフンの種類を自動置換しない。
- 前後スペースを自動削除しない。

暗黙変換によって氏名表記を変更しないためである。

並べ替え用の比較キーだけは、既存仕様どおりNFKC正規化する。これは元セルおよびコピー値を変更しない。

## 9. エラー表示

許容範囲外の文字が含まれる場合は、物理行番号、A1セル番地、検出値、Unicodeコードポイントを表示する。

例:

```text
シート上の38行目（対象セル F38）の「フリガナ」に使用できない文字があります。
半角カタカナ、半角英数字、氏名用の半角記号（-、'、.、/、()、&、_、,）、半角スペースを使用してください。
```

個人情報を共有せずに調査できるよう、問題の文字のコードポイントだけで原因を確認できる構成とする。

## 10. TSV安全性

許容文字集合には次の制御文字を含めない。

- 水平タブ`U+0009`
- 改行`U+000A`
- 復帰`U+000D`

コピー対象列全体に対するTSV制御文字検証も維持する。

氏名用記号はTSVの区切りではないため、ハイフン、アポストロフィ、ピリオド、スラッシュ、丸括弧などを含んでも列位置は変化しない。

## 11. テスト要件

### 11.1 正常系

- `ﾏﾘｱ-ｶﾞﾙｼｱ`
- `LEE-JUN HO`
- `O'NEIL.JR/2`
- `ﾁｬﾝ(LEE)`
- `ｽｰ･ﾘｰ`
- `LAST, FIRST`
- `A&B_C`
- ハイフン付きフリガナを含む通常ワークフロー
- 学生1,000人・日付300列の最大構成にASCIIフリガナを混在

### 11.2 異常系

- 全角カタカナ
- ひらがな
- 全角ハイフン
- 全角英数字
- 全角スペース
- タブ、改行、復帰文字
- 空文字または空白だけ
- `=`、`+`、`@`で始まる式状の値
- `<`、`>`、`#`、`:`などホワイトリスト外のASCII記号

## 12. 受け入れ基準

1. `ﾏﾘｱ-ｶﾞﾙｼｱ`を正常に抽出できる。
2. `LEE-JUN HO`を正常に抽出できる。
3. 許可した氏名用記号を含む値を列ずれなくコピーできる。
4. ホワイトリスト外のASCII記号、全角文字、制御文字を含む場合は対象セル付きで中止する。
5. `=`、`+`、`@`を含む式状の値を拒否する。
6. フリガナの表示値をコピー時に変換しない。
7. フリガナ昇順のメモリ内ソートを維持する。
