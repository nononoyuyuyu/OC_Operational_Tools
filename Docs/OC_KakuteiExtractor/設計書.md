## 2. 目的

`学生情報一覧`から指定期間の学生情報を抽出し、フリガナ昇順のヘッダーなしTSVとしてクリップボードへコピーする。

元シートのデータ、書式、行順、列順を変更しない。通常フィルタがある場合は、フィルタ本体を保持し、列ごとの絞り込み条件だけを解除する。

手動で非表示にされた行は再表示する。行グループは通常の行非表示とは別機能として扱い、本ツールでは開閉状態を変更しない。抽出処理は表示状態および行グループの開閉状態に依存しない。

## 3. 対象シートと入力

| 項目 | 値 |
| --- | --- |
| 実行元シート | `スクリプト用シート` |
| 取得元シート | `学生情報一覧` |
| 開始日 | `A2`、`yyyy/MM/dd` |
| 終了日 | `B2`、`yyyy/MM/dd` |
| 実行関数 | `runOC_KakuteiExtractor` |

## 4. 必須列と出力

ヘッダー行は固定せず、次の4列が同一行に各1回存在する唯一の行を採用する。

```text
学籍番号
名前
フリガナ
SA/TA
```

出力列順は次のとおりである。

1. 学籍番号
2. 名前
3. フリガナ
4. SA/TA
5. 指定期間内の日付列を元シートの左から右の順

ヘッダー行と追加列は出力しない。

## 5. 日付列

- 表示が`4/19`でも、内部値がDateならスプレッドシートのタイムゾーンで完全日付へ変換する。
- 文字列の場合は年を含む`yyyy/M/d`または`yyyy/MM/dd`を認識する。
- 年を持たない単なる文字列`4/19`から年を推測しない。
- 指定期間内の日付セルは空欄を許容する。
- 非空欄の場合は`〇`、`×`、`キャンセル`、`確定`、`定員`だけを許可する。

## 6. 値仕様

| 列 | 規則 |
| --- | --- |
| 学籍番号 | 必須。正規化後にASCII英数字 |
| 名前 | 必須 |
| フリガナ | 必須。半角カタカナ、半角英数字、半角スペース、氏名用記号 |
| SA/TA | 空欄可。非空欄の場合は正規化後にASCII英数字 |
| 日付セル | 空欄可。非空欄の場合は許可5値 |

フリガナの氏名用記号は`-`、`'`、`.`、`/`、`(`、`)`、`&`、`_`、`,`とする。

## 7. 処理上限

| 項目 | 上限 |
| --- | ---: |
| 学生数 | 1,000人 |
| 日付列数 | 300列 |
| 指定可能期間 | 最大3年間 |
| 最大出力 | 1,000行 × 304列 |

## 8. 表示状態の初期化

### 8.1 禁止事項

- 通常フィルタ本体を削除してはならない。
- `Filter.remove()`を使用しない。
- 行グループを展開または折りたたんではならない。
- 列の非表示状態および列グループを変更してはならない。

### 8.2 通常フィルタ

- フィルタ範囲とフィルタボタンを保持する。
- 各列に設定された絞り込み条件だけを解除する。
- 保存済みフィルタ表示を変更しない。
- フィルタの並べ替え状態は変更しない。

### 8.3 手動非表示行

- `showRows()`で全行を再表示する。
- `SpreadsheetApp.flush()`で結果を確定する。
- 行再表示に失敗した場合は、フィルタ条件へ触れずに中止する。

### 8.4 行グループ

- `expandRowGroupsUpToDepth()`を使用しない。
- `expandAllRowGroups()`を使用しない。
- `collapseAllRowGroups()`を使用しない。
- 既存の開閉状態を保持する。
- 折りたたまれたグループ内の行も抽出対象に含める。

行グループ展開APIは、行グループが存在しないシートや特定のシート状態で例外となる場合がある。行グループ展開は抽出結果の完全性に不要であるため、必須処理から除外する。

### 8.5 実行順序

1. 通常フィルタと条件を退避する。
2. 編集できないシート保護がないか確認する。
3. 手動非表示行を再表示して`flush()`する。
4. フィルタ条件だけを解除して`flush()`する。
5. コピー確認画面へ進む。

### 8.6 条件解除失敗時

フィルタ条件の解除中または`flush()`時に失敗した場合、退避した条件を全列へ再設定する。フィルタ本体は削除しない。

復元にも失敗した場合は、一部条件が元へ戻っていない可能性を利用者へ通知する。行グループの開閉状態はいずれの場合も変更しない。

詳細は[フィルタ解除・行再表示仕様](フィルタ解除・行再表示仕様.md)を参照する。

## 9. 確認画面

1回目の確認画面には次を表示する。

- 対象ファイル名、対象シート名
- 検出ヘッダー行とデータ開始行
- 対象期間
- 追加列を無視すること
- `SA/TA`と日付セルの空欄を許容すること
- フリガナの許容文字
- 通常フィルタ本体を残して条件だけ解除すること
- 手動非表示行を再表示すること
- 行グループの開閉状態を変更しないこと
- 抽出は行グループの状態に依存しないこと
- フリガナ昇順で取得すること

2回目の確認画面には日付列一覧、取得行数、ヘッダー行を表示する。

## 10. 同時実行と変更検出

1回目の確認後にドキュメントロックを取得し、対象データを再取得する。確認前後で対象データ、ヘッダー位置、日付列、入力期間が変化していた場合は、表示状態を変更する前に中止する。

## 11. セキュリティ

- `@OnlyCurrentDoc`を使用する。
- OAuthスコープを現在のスプレッドシートとコンテナUIへ限定する。
- 学生情報をログ、外部通信、Properties Service、Cache Serviceへ出力しない。
- 外部JavaScript、CDN、外部フォントを使用しない。
- トップレベルへ`const`、`let`、`var`を宣言しない。

## 12. テスト

### 12.1 表示状態

- `Filter.remove()`を呼び出さない。
- 条件がある列だけを解除する。
- 手動非表示行の再表示が条件解除より先に行われる。
- 行グループの展開・折りたたみAPIを呼び出さない。
- 行グループAPIが例外を投げるモック環境でも処理できる。
- 保護または行再表示失敗時は条件を変更しない。
- 条件解除失敗時は元条件を復元する。
- 通常フィルタがなくても正常に処理する。

### 12.2 抽出

- 任意行のヘッダー検出
- 日付型見出し
- 追加列の無視
- 空欄セルの列位置維持
- フリガナの留学生名表記
- 学生1,000人、日付300列
- Chrome・Safariのコピー退避

## 13. 受け入れ基準

取得済みの表示値マトリクスは行・列オフセットを検証器へ渡し、対象範囲全体の切り出し配列を作らない。出力列ラベルは検証1回につき1度計算する。指紋用の行は出力値と参照を共有し、JSON化する行だけを `[シート行番号, ...出力値]` の旧形式へ展開する。確認前とロック取得後の2回の読込・指紋比較は維持する。詳細と比較値は [性能検証](性能検証-20260908.md) を参照する。

1. 実行後も通常フィルタ本体が残る。
2. フィルタの絞り込み条件だけが解除される。
3. 手動非表示行が再表示される。
4. 行グループの開閉状態が変化しない。
5. 行グループが存在しないシートでもエラーにならない。
6. 行グループが折りたたまれていても該当データが抽出される。
7. 行再表示失敗時にフィルタ本体と条件が変更されない。
8. 条件解除失敗時に元条件が復元される。
9. 抽出結果の列数、空欄位置、行順が維持される。
10. 元データ、書式、行順、列順を変更しない。
