# TSV安全性と取得上限

## 数式として解釈される値

コピーする全セルについて、先頭の `=`、`+`、`-`、`@` を検査します。検査時だけNFKC正規化し、先頭の空白・制御文字・ゼロ幅文字を除いて判定するため、全角互換文字や先頭空白を付けた値も拒否します。タブ・改行の既存の拒否も維持します。

この検査は初回確認とロック取得後の再検証の両方で実行されます。問題が見つかった場合は対象セルを示して中止し、通常フィルタ・行の表示状態を変更せず、コピー画面を開きません。元セルや安全な氏名は書き換えません。

フリガナに使用できる文字の規則と、TSV出力の安全性規則の両方を満たす必要があります。例えば `LEE-JUN HO` の内部ハイフンは許可しますが、先頭ハイフンの値は出力安全性のため拒否します。先頭が記号の正当な氏名を扱う場合は、管理者が入力内容と貼り付け先を確認してください。自動的にアポストロフィーを付けるなどの加工は行いません。

## 読み込み量

`ocKakuteiGetConfig_()` の `maxReadCells` は500,000です。ヘッダー検索開始行から最終使用行、1列目から最終使用列までの長方形のセル数を、ソースシートの `getRange()` / `getDisplayValues()` より前に検査します。

学生1,000人・日付300列・固定4列と1行のヘッダーは304,304セルであり、上限内です。ただし、離れた場所の不要な値や追加列も使用範囲に含まれます。上限超過時は、それらを整理してから再実行してください。学生数・日付列数の既存上限も引き続き適用します。

## 検証

リポジトリルートで次を実行します。Node.js 18以降を使用し、外部npmパッケージは不要です。

```sh
node --test Tests/OC_KakuteiExtractor/*.test.js
```

`safety.test.js` は危険な先頭文字、互換文字・不可視文字、安全な名前の保持、上限境界、読み込み前の拒否、公開実行関数の副作用抑止を検証します。既存のロジック・表示状態・ワークフロー・静的テストと同じCIで実行します。

実スプレッドシート上の権限、クリップボード、Excel・Googleスプレッドシートの貼り付け動作は別途実機確認が必要です。モックテストだけで実機確認済みとは扱いません。
