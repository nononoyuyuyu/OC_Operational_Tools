# アプリアイコン

丸い輪の開口部に点を置いた共通マークを使用する。内蔵imagegenで原画を生成し、Windows・Android・iOS・Webとアプリ内のOCOマークに使用している。

## 原画と再生成

- 原画: `Source/OpenCampusOrganizer/assets/branding/oco-master.png`
- 白をマーク、黒を背景として配色へ変換する。テーマ切り替え時に形を描き直さない。
- Windows: 全5配色、16〜256pxの9サイズを含む円形ICO。アプリ内のマークも円形。
- Android: 旧形式は円形PNG。Android 8以降は前景と背景を分けたadaptive iconを使い、ホームアプリ側のマスクに対応する。通知用は白い前景。
- iOS: 透過チャンネルのないRGB画像。外周の角丸はOSに任せる。
- Web: 通常アイコンは円形、maskable版は背景付き。

WindowsのPowerShellで、アプリのディレクトリから実行する。追加のPythonパッケージは不要。

```powershell
./tool/generate_icons.ps1
../../Tests/OpenCampusOrganizer/icon_assets_test.ps1
```

配色は `lib/design/color_schemes.dart` を参照する。Androidは全5色のPNG・adaptive iconを生成し、背景色も `android/app/src/main/res/values/launcher_<theme>.xml` に出力する。

## 共通の更新順序

`AppearanceController` は保存色の復元とユーザーの選択を同じOS更新キューへ流す。実行中の要求が終了してから最新色を適用し、未着手の中間色は省略する。画面の配色は即座に切り替える。保存は選択順を維持し、古い処理の失敗では最新選択のエラー表示を上書きしない。OS更新が失敗しても次の要求や同じ色での再試行を続行する。破棄後は未着手のOS更新を開始しない。

iOS・WebではOSアイコンの動的切替は実装していない。アプリ内の配色変更と静的アイコンを維持し、未実装のMethodChannelを呼ばない。

## Windowsの表示連動

ウィンドウの大小アイコンはEXEに埋め込んだ各配色から読み込む。タスクバーとショートカットには、全サイズを保持した配色別ICOファイルを渡す。形式は [RelaunchIconResourceの仕様](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-relaunchiconresource) に従い `ICOの絶対パス,0` とする。

0.4.8の修正候補では次の順序で更新する。実際のタスクバー・スタート描画の確認は継続中。

1. 埋込画像からICOを生成し、`%LOCALAPPDATA%\OpenCampusOrganizer\appearance` に保存する。ファイル名に内容のSHA-256を含める。同じ内容は再利用し、読み込み済み画像の上書きを避ける。一時ファイルの書込・flushが成功してから最終名へ移す。
2. 実行中のEXEと起動先が一致する、現在のユーザーのスタートメニュー・デスクトップ・既存タスクバーピン留めのリンクを保存し、COMオブジェクトを解放する。引数と作業フォルダーを保持する。変更不要な読取専用リンクは書き直さない。通知は保留する。
3. ウィンドウの再起動コマンド・表示名・ICO参照を揃えてから、大小のウィンドウアイコンを差し替える。AppUserModelIDはプロセス・リンク・ウィンドウで固定する。
4. [SHUpdateImage](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shupdateimagew) による個別画像の通知に加え、`SHCNE_ASSOCCHANGED` を通知する。その後で、保存済みリンクと登録済みAppsFolder項目に `SHCNE_UPDATEITEM / SHCNF_FLUSH` を通知する。長いファイルパスでも通知できるよう、絶対PIDLを渡す。同じ配色の再選択でも再送する。

全体のキャッシュ更新通知ではデスクトップのアイコンが再描画される場合がある。Windows 11で全体通知だけではタスクバーが更新されない場合への対処として、後続の個別リンク通知も行う。[Chromiumの実装](https://github.com/chromium/chromium/blob/main/chrome/browser/profiles/profile_shortcut_manager_win.cc) もこの順序を採用している。ただし、他アプリの実装例はOCOの実表示の検証を代替しない。

DPI変更は大小アイコンの更新だけを行う。Shellの再初期化時は選択中の配色を再適用する。既存リンクがアップデートでEXE参照へ戻った場合も、起動時の保存配色の適用でICO参照へ更新する。ピン留めの追加・解除、Windows全体のキャッシュ削除、Explorerの再起動は行わない。

ICOはアプリ終了後もショートカットから参照されるため保持する。同じ5画像なら切替回数にかかわらず5ファイルを再利用する。旧画像を参照するリンクを壊さないよう、アップデート時にも過去の画像を自動削除しない。

ネイティブテストは実Win32ウィンドウ、実際のShell画像リストと画像取得API、画像変更通知の受信、全5配色・各9サイズ、5色の3周、同色再試行、リンク再作成、DPI、書込失敗と再試行を確認する。テスト用のアプリIDと画像保存先を製品から分離する。原因調査、検証結果、実際のスタート／タスクバーの描画として未確認の範囲は [再発調査記録](Windowsアイコン再発調査-20260922.md) を参照する。

## Androidの表示連動

[activity-alias](https://developer.android.com/guide/topics/manifest/activity-alias-element) を配色ごとに用意し、起動先はすべて画面を表示しないLauncherActivityとする。LauncherActivityは入口専用のtaskAffinityを持ち、MainActivityを別タスクで開いて直ちに終了する。既存のMainActivityはsingleTaskで再利用する。入口を操作画面のタスクに残さないことで、テーマ変更時に旧aliasが無効化されても操作画面を終了させない。Androidのアプリ表示名は全配色で「OC」とする。選択した1個だけをPackageManagerで有効化する。API 33以降は一括更新、API 24〜32では新しい入口を先に有効化してから旧入口を無効化する。DONT_KILL_APPを指定する。ただし、この指定だけではaliasから開いたActivityの終了を防げないため、上記のタスク分離も行う。処理用のActivity・エンジン・サービスは無効化しない。保存された配色はFlutterから起動時にも同じ経路で反映する。ホームアプリのキャッシュ更新には時間がかかることがあり、OSのテーマアイコンが有効な場合はOS側の色が優先される場合がある。

Android SDK・エミュレーター起動済みの環境で `android` ディレクトリから `./gradlew :app:connectedDebugAndroidTest` を実行すると、全5色の3周・各色の二重適用、起動アイコンが常に1個であること、MainActivityが有効であることに加え、ホーム画面の入口から開いた画面が遅延するパッケージ変更通知の後も前面に残ることを検証する。全配色の変更後に同じ画面・エンジン・タスクが維持されること、背景からアイコンおよび通知の経路で同じ画面へ復帰すること、表示名がOCであることも確認する。Androidネイティブコード・テストの変更時はCIのAPI 35エミュレーターでも実行する。テストはdebug専用で、AndroidX Testは配布用APKに含まれない。

## 生成指示

内蔵imagegenを使用。最初に丸い輪と点を中心とした単純なマークを依頼し、輪と点だけを残す修正を行った。透過指定が市松模様として描かれたため、その画像は採用せず、最後に次の指示で白黒の原画を生成した。

> この白いC型の輪と点は形・位置を保ち、背景だけを全面の純黒（#000000）にする。中央の穴と余白も黒にする。市松模様とテクスチャをすべて除去する。輪と点は均一な純白（#FFFFFF）にし、輪郭を滑らかにする。平面的な白黒画像とし、影や他の要素を追加しない。

生成原画をそのまま保存し、配色変換・縮小・ICO梱包は再生成スクリプトで行う。
