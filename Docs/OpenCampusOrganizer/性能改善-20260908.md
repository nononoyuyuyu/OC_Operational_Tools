# 性能・容量・メモリ改善（2026-09-08）

基点: `3f699682d24ea7a5913f45d322c11fb858fcfddd`（PR #25取り込み後）。この変更は性能に限定し、Discordの更新順序・送信前記録・権限検査・承認済み対象・旧履歴形式を変えません。

## 実装の比較

| 対象 | 変更前 | 変更後 | 制約 |
|---|---|---|---|
| 投稿者の集計 | 投稿者別に全投稿リストを保持・ソート | 件数と最初/最後の日時を取得時に1パス集計 | 投稿CSV向けの全投稿と最終時刻ソートは維持 |
| 投稿オブジェクト | 投稿ごとに別の投稿者、解決済み全投稿リストをもう1つ作成 | 元投稿者をIDごとに共有、私有リストを順次置換 | 公開境界の不変コピーは維持 |
| 解除プレビュー | 全メンバーの詳細を保持 | 対象ロール保持者だけの詳細を保持 | 全ページ検証、取得量上限、カーソル進行は維持 |
| CSV | 全行文字列配列、全体文字列、UTF-8、汎用整数配列、Uint8List | 32,768文字程度のバッチでUTF-8へ変換 | 最長1行分は上乗せ。最終バイト配列O(B)は必要 |
| サーバー情報取得 | サーバー情報・Botメンバー・チャンネル一覧を逐次取得 | 最大3つの独立GETを同時実行 | 要求回数は同じ。読取グループ以外はFIFO直列 |
| Android配布 | 単一の汎用APK | 任意選択でABIごとのAPKを生成 | 既定のAPK名・署名方式は変更しない |

## 並列化の境界

`DiscordTransport.readBatch()` は1～3件のGETだけを受け付けます。1グループがFIFOキューの1項目であり、全読取が終了するまで後続の通常要求・PUT・DELETEは進めません。1件が失敗しても残りの読取が終了するまでバリアを解放しません。ロール更新ループ自体は逐次のままです。

同じ正規化ルートまたは学習済みの同じレート制限バケットを含むグループは、グループ全体を直列実行します。初回応答まで異なるルートの共通バケットは分からないため、未学習ルートの既送信要求の重なりを完全には防げません。バケット判明後は上記の直列化と429待機を適用します。

並列読取は待機後にバケット/全体期限と40要求/秒ガードを再検査します。全体制限の期限は短縮せず延長のみ採用します。Tokenの変更・取消は送信前と読取応答受領後に確認します。キューは実行中を含め128グループまでに制限します。`parallelReads: false` で同じコードを逐次実行に戻して比較できます。

## メモリ削減の意味

投稿数をM、投稿者数をU、全メンバー数をG、対象者数をT、CSVバイト数をBとすると、投稿者別集計の追加保持量をO(M)参照からO(U)集計値へ変更します。集計の時刻ソートも不要になりますが、全投稿CSV用の最終ソートO(M log M)は残ります。解除プレビューの詳細保持量はO(G)からO(T + 1ページ)です。走査件数は重複排除前に数えるため、対象者が少なくても無制限には走査しません。

CSVは全体文字列と汎用の全バイト整数配列を作りません。ただしUTF-8チャンクと最終連続配列が必要であり、ファイルへ直接書く完全なストリーミング出力ではありません。出力のBOM・CRLF・末尾改行・数式対策・列順を変えず、容量そのものは同じです。

## ベンチマークとテスト

```sh
cd Source/OpenCampusOrganizer
flutter pub get --enforce-lockfile
flutter test --no-pub ../../Tests/OpenCampusOrganizer
# 旧/新を別のDartプロセスで実行。実データ・秘密情報を使わない。
dart run tool/csv_benchmark.dart
```

CSVベンチマークは架空6,000行で旧エンコーダと新エンコーダを比較します。各モードを新しいVMで実行し、出力バイト数・チェックサム・時間・開始RSS・最大RSSをJSONで記録します。RSSにはVM/JITも含まれ、Flutter実機のヒープ量とは異なります。単発計測は端末全体の高速化率を保証しません。回帰テストでは旧実装と全バイトを直接比較します。

`parallel_reads_test.dart` は20msの模擬応答でコンテキスト取得の逐次/並列を比較し、要求回数と最大同時実行数を検証します。実Discordの待ち時間ではありません。共有バケット、全体429の期限延長、40要求/秒、キュー上限、失敗時のバリア、中止・接続変更も検証します。

`extraction_memory_test.dart` は順不同時刻・重複・Bot・最小投稿数・現在の氏名・全ページ確認・上限を検証します。大きなメンバー入力はページごとに生成し、テスト自身が全メンバー詳細を先に保持しないようにしています。

## ABI別APK

Windowsの従来の配布環境で、既存の署名鍵を使用します。

```powershell
./tool/build_android_release.ps1 -SplitPerAbi
```

`armeabi-v7a`、`arm64-v8a`、`x86_64` を区別したAPK名とSHA-256が出力されます。全APKの存在・署名・非debuggableを検証してから配布先へコピーします。指定なしは従来の単一APKです。端末に対応する1つを配布してください。

このPRは配布署名鍵の生成・Release公開を行いません。実署名Releaseでの汎用APKとABI別APKのサイズ比較・上書き導入は別途必要です。Debug APKのサイズをReleaseの指標として使いません。`Tests/OpenCampusOrganizer/android_release_layout_test.ps1` は出力レイアウトと構文だけを検査し、署名処理を実行しません。
