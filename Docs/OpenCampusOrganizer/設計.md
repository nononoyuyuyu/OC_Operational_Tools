# Open Campus Organizerの設計

## 対象と構成

Flutter 3.44.4 / Dart 3.12.2を使用する。Windowsを現在の開発・実行環境とし、Android・iOSのプロジェクトを同じアプリに含める。ブラウザ版は実BotのTokenを扱わないサンプル専用とする。

```text
Source/OpenCampusOrganizer/
  lib/
    main.dart                         依存関係を組み立てる入口
    app/                              共通ナビゲーション、ツール一覧、設定、履歴
    design/                           色、文字、余白、共通部品
    core/
      tool_module.dart                機能と共通画面の接点
      tool_activity.dart              共通履歴の要約モデル
      tool_status.dart                接続状態・通知の共通表示モデル
      appearance.dart                 配色設定と保存
      pending_task.dart               再開する処理の永続化
      task_host.dart                  処理とOSの実行状態の契約
      runtime_controller.dart         継続設定・通知・終了制御
      ports.dart                      資格情報、保存、ファイル出力の契約
      scoped_store.dart               機能ごとの保存名の分離
      platform/                       OSの保存・共有・ウィンドウ外観・旧版移行
    features/kakutei/
      kakutei_module.dart             確定ロールの登録情報
      domain/                         UI・Flutter・HTTPに依存しない業務処理
      application/                    画面状態とユースケースの調整
      data/                           Discord REST、サンプル、操作記録
      presentation/                   入力・一覧・確認ダイアログ
  windows/ android/ ios/ web/         各環境の起動処理
  tool/generate_icons.ps1             共通原画から全OSアイコンを再生成
  tool/generate_windows_icons.ps1     5配色のWindowsアイコンの再生成
  tool/build_windows_installer.ps1    依存検証とWindowsインストーラーの作成
  tool/build_android_release.ps1      配布鍵の保管と署名付きAPKの作成
  installer/windows/                 Inno Setup定義、ランタイム判定、依存バージョン
Tests/OpenCampusOrganizer/            自動テスト
Docs/OpenCampusOrganizer/             日本語の設計・操作・検証文書
```

依存方向は `presentation → application → domain`、`data → domain / core` とする。`domain` は外部依存をインターフェースとして受け取る。`app` は `ToolModule` とcoreの共通表示モデルを参照し、確定ロールのモデルやDiscord APIを参照しない。具象クラスの選択は `main.dart` で行う。

配布処理はアプリの業務処理から分離する。Windowsインストーラーは共有VC++ランタイムを不足時のみ導入し、設定・履歴を引き継ぐか削除するかを選択できる。共有ランタイムは削除しない。AndroidのRelease署名はビルド時の環境変数で受け取り、秘密鍵はソースに含めない。具体的な作成・保管・導入手順は [配布](配布.md) を参照する。

## 機能追加とUI変更

1. `features/<機能ID>` に機能固有の業務処理・接続処理・画面を作成する。
2. `ToolModule` を実装し、ID、名称、アイコン、状態通知、画面、設定を提供する。作業画面は有限の幅・高さを受け取り、必要なスクロールをツール内で管理する。履歴は `ToolActivity` の一覧、通知表示、IDに対応する詳細画面を提供する。詳細画面も有限の幅・高さに収まるようにページ送りや局所スクロールを管理する。
3. `main.dart` のモジュール一覧へ登録する。ツール一覧とPCナビゲーションには登録内容が反映される。共通履歴は全モジュールの要約を日時順に統合し、画面の高さと文字サイズに応じた件数でページ表示する。複数ツールがある場合は絞り込みも表示する。
4. 保存領域は `ScopedStore` で名前空間を分ける。別機能の内部クラスや保存キーを直接参照しない。
5. 外部接続や保存が必要な場合は、まず契約を定義してから具象アダプターを実装する。

接続表示には `ToolConnection`、スマホ通知には `ToolFeedback` を返す。不要な機能はそれぞれnullを返す。通知には操作ごとに更新するrevision、文面、進捗、中止・閉じるコールバックを渡す。`app/mobile_feedback_host.dart` が共通画面で一度だけ表示し、非表示のツール・履歴・設定画面から同じ通知を重複させない。PCの固定通知欄は従来どおりモジュールが提供する。

モジュールはアプリ起動時に初期化され、終了時に破棄される。画面を移動しても各機能のコントローラーと入力画面を維持する。継続処理を持つ機能は `TaskHost` へ開始・進捗・終了を伝え、共通の `RuntimeController` へ保存停止・再開・中止のコールバックを登録する。共通画面とOS側はDiscordのモデルを参照しない。動的プラグイン読込と複数端末間の同期は実装していない。

UIを変更する場合は `presentation`、共通の外観は `design`、Discord仕様への追従は `data` を中心に変更する。業務処理を別のUIへ移す際も、抽出・権限計算・CSV・ロール操作は再利用できる。

## 画面設計

既存Windowsツールの画面・XAML・画像は使用していない。初期配色はダークとし、白・青、ウォームグレー、セージグリーン、アプリコットを含む5色を切り替える。保存済みの配色は引き継ぐ。色の値は design/color_schemes.dart、部品の形状・文字は design/theme.dart に分ける。各画面は共通の `ColorScheme` を参照し、操作状態と外観設定を分離する。設定は `app_v1_appearance` に保存する。実装方針や将来の開発計画を説明する文言は画面に置かない。調査根拠と判断は [UI再設計](UI再設計.md) にまとめる。

- 幅860論理ピクセル以上のPC・タブレット: サイドバー。設定は左下に固定し、その下に接続状態を置く。その他: ツール・操作履歴・設定の下部ナビゲーション。接続状態は右上に置く。起動先はツール一覧。PCには各ツールへの直接リンク、狭い画面のツール画面には一覧への戻るボタンも置く。
- スマホ表示の条件はAndroid・iOSかつ画面短辺600論理ピクセル未満。判定を `design/device_layout.dart` に集約し、回転しても本文・CSVを突然表示しない。狭いWindowsウィンドウはPCの機能を維持する。スマホでキーボードが出ている場合と、高さ480未満のツール画面では、下部ナビゲーションを隠して入力・一覧に高さを割り当てる。
- 確定ロールは幅840以上かつ、通知欄と12の余白を除いた高さが520論理ピクセル以上なら、条件と対象者・実行結果を横に配置する。それ以外は条件設定・対象者確認・実行結果を切り替える。処理結果を下へ追加して画面全体を伸ばさない。
- PCの対象者一覧は `AdaptivePageList` がヘッダー・操作欄を除いた高さと文字サイズから1ページの人数を算出する。リサイズ時は先頭の対象者を維持し、検索・一覧種別の変更では先頭に戻す。名前・ユーザーID、投稿本文で検索できる。長い投稿は行を開いて全文を確認する。
- スマホの対象者一覧は `MobileResultsPanel` のListViewで、名前と処理予定だけを最小40の行に表示する。一覧の親にスクロールを置かず、検索と付与ボタンを残す。回転・リサイズではスクロール位置を保持する（末尾は表示範囲に収める）。新しい抽出結果・検索では先頭へ戻す。本文・添付URLのチェック、投稿タブ、CSV出力を省き、抽出時の本文・添付URLフラグもfalseにする。保存済みのフラグ自体は上書きしない。
- PCの通知・エラー・進捗は高さを確保した下部欄へ表示する。スマホでは共通の重ね表示にし、通常通知は6秒、エラー・進捗は手動で閉じるか処理が終了するまで残す。読み上げ利用時は通常通知も自動消去しない。長文は通知内だけでスクロールし、新しい通知は先頭から表示する。別画面への移動・テーマ変更で通知を再表示せず、同じ文面の別操作はrevisionで区別する。通知のタップではダイアログを開かない。一括解除0人も同じ表示経路を使う。
- 接続済みはprimary、未接続はonSurfaceVariant、接続中・サンプルはtertiaryを使い、ラベルとアイコンを併用する。接続済みはBotセッションの初期化完了を表し、ネットワークの常時監視ではない。アイドル時の接続状態は下部通知欄には表示しない。
- Androidはedge-to-edgeで描画し、共通の `ThemedSystemBars` からテーマに合わせたアイコンの明暗とコントラスト背景の無効化を指定する。Android 15以降はネイティブテーマでも透明なnavigationBarColorを明示し、ウィンドウ背景の明るさからLIGHT_NAVIGATION_BARSが強制される経路を抑止する。システムナビゲーション領域はFlutterのsurfaceが下に続く。Android 8〜14用にはsurfaceのバー色も指定する。Android 7のナビゲーションボタンはOS標準の見た目を維持する。ホームアプリ側の別の色指定による上書きは制御できず、Android 15のエミュレーターの3ボタン操作で未解消の表示を記録している。iOSのホームインジケーター自体はOSが管理する。
- 小さいウィンドウや文字拡大で最小限の入力・操作欄を収められない場合も、スクロールは該当パネル内に限定する。通常のPC表示では条件欄もスクロール不要とする。
- 大画面では工程タブを表示せず、右欄の対象者・実行結果だけを切り替える。局所スクロールの有無でWidgetの親構造を切り替えず、高さだけを変える。小さい高さへ縮めた後に戻しても、一覧の先頭対象者を維持する。
- 履歴の作業領域が幅900以上・高さ420×文字倍率以上の場合、左に履歴一覧、右に選択した詳細を並べる。それ以外は「履歴」「詳細」を切り替える。両パネルは同じWidgetを維持し、リサイズをまたいで選択した操作とページの先頭を保つ。
- 履歴一覧と対象者ごとの結果は `AdaptivePageList` でページ表示する。詳細は名前・ID・失敗理由を実際の幅と文字サイズで測り、行の高さを決める。長い理由は省略せず、1行分すら収まらない場合だけパネル内でスクロールする。成否の右側に専用の余白を取り、スクロールバーが重ならないようにする。
- サーバー・チャンネル・ロール、日時、Bot除外、本文・添付URL、最小投稿数が変わると、以前のプレビューを破棄する。
- 一括解除の入口は対象ロール選択欄の直下に置く。投稿抽出とは独立し、対象者一覧と注意事項のチェックを一つの確認画面で表示する。ロール名の入力は要求しない。実行前の確認ダイアログ内は高さ200のスクロール一覧で、作業画面や履歴のページ式一覧とは別の表示である。

## Discordとの接続

日時の入力精度は分単位とし、終了入力は `parseJstMinuteEnd` でその分の最後の時刻に変換する。開始・終了がともに09:00なら09:00:00以上09:01:00未満となる。`Conditions.end` は従来どおり包含する上限時刻であり、終了が空欄なら抽出開始時点までとする。終了分の次の分をAPIカーソルに使うため、秒や小数秒の投稿を取得段階で落とさない。

[Discord API v10](https://docs.discord.com/developers/reference)へHTTPSで接続する。Botを使用し、ユーザーアカウントのTokenは受け付けない。接続先はコード内で固定し、リダイレクトに認証ヘッダーを送らない。

- サーバー一覧は200件、投稿は100件、メンバーは1,000件ごとにページを取得する。
- 投稿の取得対象は通常のテキストチャンネル（type 0）。スレッド、フォーラム、アナウンスチャンネルは一覧に含めない。期間・Bot条件を満たす投稿は保持の有無にかかわらず100,000件、一括解除で走査するサーバーメンバーは100,000人を超えると停止する。
- ページのカーソルが進まない、取得に失敗する、取得上限を超える場合は部分結果を確定しない。
- 本文・添付URLにはMessage Content Intent、一括解除にはServer Members Intentが必要。Applicationのフラグを接続時に確認する。
- チャンネル権限はサーバー権限に加え、everyone、複数ロール、メンバー個別の上書きを順に計算する。
- `@everyone`、外部管理ロール、管理者ロール、Botと同順位以上のロールは操作しない。
- ロール更新は直列実行する。開始時と、5秒経過または20人処理した時点で権限・階層・ロール設定を再照合する。照合ではチャンネル一覧を取得しない。各人の現在の保有状態は毎回取得する。照合の間隔内に対象ロールの名称等が変わる競合は残る。Discord側の更新権限検証で拒否された場合は、その時点で後続を止める。
- 投稿取得は終了日時から生成したSnowflakeを最初の `before` に指定し、終了日時より新しい投稿の走査を避ける。日時と同じミリ秒の投稿を除外しないよう次のミリ秒を境界にし、本文の時刻でも両端を検証する。
- 投稿者が8人以上でServer Members Intentが有効なら、一覧APIを最大4ページ使用してまとめて照合する。未発見者は個別照会し、一覧の途中取得を退出と誤認しない。一覧取得が403なら個別照会へ切り替える。その他の取得失敗は中止する。
- HTTP 429はサーバー指定の待ち時間を守る。トランスポート内は最大6要求とし、正常な待ち時間が300秒以内なら保存タスク側で待って再開する。不正な値や300秒を超える指定は停止する。通信失敗した更新要求は、タスク側で現在のロールを再照合してから必要な場合だけ送る。
- 毎要求の固定80ms待機は設けない。Discordのバケット・主要リソース別の待機期限を記録し、経過済み時間を差し引く。全体は直近1秒40要求以下に抑え、globalの429は全体に適用する。
- HTTP要求は25秒でタイムアウトし、進行中の要求を中断する。利用者が中止したときは送信済みの更新の応答を確認し、次の対象から停止する。

根拠: [ロールと権限](https://docs.discord.com/developers/topics/permissions)、[レート制限](https://docs.discord.com/developers/topics/rate-limits)、[メンバーの取得](https://docs.discord.com/developers/resources/guild#list-guild-members)、[Applicationフラグ](https://docs.discord.com/developers/resources/application#application-object-application-flags)。

## データの保存と復元

Bot Tokenは `CredentialStore` 経由で [flutter_secure_storage](https://pub.dev/packages/flutter_secure_storage) に保存する。Tokenを含むHTTP例外やレスポンス本文はログ・エラー画面に渡さない。通常のローカル保存にはTokenを入れない。

保存済みTokenで接続すると、Bot IDに対応する `kakutei_v1_settings_<Bot ID>.data` から前回のサーバー、サーバーごとのチャンネル・対象ロール、開始・終了日時、最小投稿数、Bot除外、本文・添付URLの選択を復元する。設定にはTokenを含めない。保存しない接続・サンプル・別Botの接続では前のBotの値を流用しない。書き込みは順序を保ち、読み戻す際は保留中の書き込みを待つ。保存先は `LocalStore` として注入する。

保存されたチャンネルが閲覧できない、対象ロールが削除されている場合は未選択とし、別の対象へ自動で置き換えない。サーバーが見つからない場合も選び直す。読み取れない設定はエラーを表示し、起動時に初期値で上書きしない。設定の復元だけでは処理を実行せず、未完了の保存タスクがある場合だけ自動再開する。

操作記録は `getApplicationSupportDirectory()/open_campus_organizer/v1/` 配下の `kakutei_v1_operation_<ID>.data` に保存する。先頭行に版、操作条件、承認された対象者を記録し、その後は変更された行だけを追記する。

```text
全対象を未処理として保存
→ 対象の送信前記録を保存・flush
→ Discordのロール更新
→ 応答結果を保存・flush
→ 全件の最終状態と終了時刻を保存
→ 設定がオンの場合のみ結果CSVも保存
```

記録が保存できない場合は、その後の更新を止める。途中で終了した記録は、送信中を「結果未確認」、未送信を「未処理」として復元する。追記末尾の未完了行は採用しない。未知の形式や途中の破損は黙って無視しない。履歴と別に保存した承認済みタスクが一致する場合だけ再開する。0.3.x以前の未完了履歴だけを自動実行することはない。

結果CSVの自動保存は初期オフで、ツール設定から選択できる。オンなら同じディレクトリの `kakutei_v1_result_<ID>_csv.csv` に残る。PC・タブレットでは「操作履歴」から任意の場所へ書き出せる。スマホは出力UIを省くが、内部の記録形式は変えない。既存のCSVと履歴は自動削除しない。記録・CSVにはメンバーのIDと表示名が含まれる。OSの利用者領域に保存するが、記録ファイル自体の暗号化はしていない。

共通履歴にはツール名、操作、対象、サーバー、結果、日時を表示する。確定ロールの記録形式は従来のschema 1を維持し、既存履歴の変換は不要。選択・詳細画面のキーはツールIDと操作IDの組にする。詳細のスクロール位置は独自のControllerで管理し、従来の結果展開画面でも開閉状態の保存キーと衝突させない。

`OperationRows` は最大32行の葉を持つ不変の木で、変更行の葉と経路だけをコピーする。`OperationReport` はこの値を共有し、成否の件数は各節点の集計値から取得する。Journalは共有節点を飛ばして変更行だけを追記し、送信前inFlightと送信後のflush頻度を変えない。書込キャッシュは現在の操作1件までとし、完了・保存失敗時に解放する。実ファイルI/Oは `FileLocalStore` を `NativeStore` と測定で共用する。

`IndexedOperationJournal` は要約を30件ずつ取得し、選択された詳細は `find(id)` で1件だけ読む。Controllerは読み込んだ要約と直近の実行結果を持ち、全履歴の詳細を保持しない。`PagedActivityModule` は共通画面の追加ページ取得を仲介する。原本 `operation_<ID>` に加えて、ID・日時・終了状態だけの `history_index` と1操作1ファイルの `history_summary_<ID>` を保存する（実キーには `kakutei_v1_` が付く）。索引がない旧版や派生索引の破損時には原本を1件ずつ読んで再生成する。起動時には未完了索引を必ず原本で再照合する。詳細の破損は読み込み時に明示し、自動削除しない。保存方針と測定は [0.4.1の性能検証](履歴と抽出の性能改善-0.4.1.md) を参照する。

投稿本文と添付URLは指定された場合のみ抽出結果に保持し、アプリの操作履歴には保存しない。CSVはUTF-8 BOM、CRLF、全セルの引用符処理、数式として解釈される値の無害化を行う。Discord IDはExcelの桁落ちを防ぐため先頭にアポストロフィを付ける。

抽出条件の `retainMessages` は初期trueで、旧形式の保存済み再開条件もtrueとして読む。スマホから開始する抽出だけfalseとし、投稿単位の一覧を作らず件数・最初/最後の日時を集計する。falseのときだけ最小投稿数未満の投稿者をメンバー照合から外す。走査・重複排除・権限・不完全結果の拒否は両モードで共通。`Extraction.messageCount` は投稿一覧の保持数と独立した採用件数。PCの投稿CSVは従来どおり全投稿を保持する。

## プラットフォームの境界

### 処理の再開と終了

`kakutei_v1_pending_task.data` はschema 1で、処理ID・Bot ID・抽出条件または承認済みロール計画・手動対応待ちの状態を保存する。Tokenは含めない。ロール計画は履歴へ先に保存し、続いてタスクを保存してからDiscordを更新する。対象者と操作内容を再開時に広げず、履歴の完了行を維持する。送信中だった人は現在の保有状態を照合し、既に目的の状態ならスキップする。履歴の終了記録後・タスク削除前に終了しても再送しない。破損したタスクや欠けた履歴は自動的に作り直さない。

抽出と解除プレビューは取得を最初からやり直す。抽出の終了日時が空欄ならタスク作成時刻に固定し、再試行で対象期間を延ばさない。抽出後は対象者の確認を待ち、ロール操作には別の承認が必要。通信失敗・タイムアウト・HTTP 5xxは2、5、10、30秒の順で待ち、以後30秒間隔で再試行する。429は指定された間隔を優先する。認証・権限・記録の異常は自動再試行しない。手動対応待ちのタスクは設定の「再開」「取り消す」で扱う。利用者の中止は終了状態を保存し、自動再開から外す。

再起動後の自動接続には保存済みTokenを使い、承認時と同じBot IDであることを確認する。Tokenを保存していない場合は同じBotへの手動接続を待つ。保存停止は送信中の応答と記録を待ってから終了する。電源断・OSによる強制終了では終了コールバックを保証できないため、送信前後の永続記録を復元根拠とする。

| 環境 | 継続・終了方式 |
| --- | --- |
| Windows | `TaskRuntime` が閉じる操作を受ける。トレイ設定は初期オフで、終了確認後に保存停止する。オンならウィンドウを隠し、通知領域から再表示または終了できる。テーマのICOも反映。名前付きmutexで同じWindowsセッションの二重起動を防ぐ。ログオン時の自動起動は登録しない |
| Android | `OcoApplication` の1個のFlutterEngineをActivityと非公開のdataSync Foreground Serviceで共有。進捗・結果をOS通知へ表示し、進捗通知から中止できる。完了後の自動終了は初期オンで、背景にある最後のロール操作が完了した場合だけActivityとEngineを終了する。前面・抽出・取消では終了しない。オフなら処理サービスだけを終了する |
| iOS | iOS 26 / Xcode 26以降はBGContinuedProcessingTaskを登録し、利用できなければUIApplicationの期限付き継続へ切り替える。進捗と結果を通知し、期限切れは保存停止する。前面に戻ると再開する。アプリを強制終了するAPIは使わず、完了時に継続権を返してOSへ委ねる |

Android 15以降のdataSync継続には24時間内で合計6時間の制限があり、時間切れはサービスを止めて次回の前面復帰を待つ。OSや利用者による強制停止、端末の省電力設定を越えて実行を保証しない。AndroidのBOOT_COMPLETED登録も行わない。根拠: [Androidの時間制限](https://developer.android.com/develop/background-work/services/fgs/timeout)、[FlutterのキャッシュEngine](https://docs.flutter.dev/add-to-app/android/add-flutter-screen)、[iOSの継続処理](https://developer.apple.com/documentation/BackgroundTasks/performing-long-running-tasks-on-ios-and-ipados)。

共通の設定は `app_v1_runtime.data` に保存し、トレイとAndroidの自動終了を個別に扱う。通知許可がなくても保存と処理は続け、OS設定で通知を許可する案内を表示する。

正式名称は `Open Campus Organizer`、略称は `OCO`、配置フォルダは `OpenCampusOrganizer`、DartパッケージとWindows実行ファイルは `open_campus_organizer` とする。リポジトリのURLと独立したGASツールの名称は維持する。

WindowsではProductNameの変更によりアプリ保存先も変わる。初回の保存領域準備で、同じ会社名の配下にある旧版から設定・履歴・CSVと暗号化済みの資格情報ファイルを新領域へコピーする。旧ファイルと既存の新ファイルは上書きしない。完了マーカーにより、保存Tokenを削除した後の再取り込みを防ぐ。移行に失敗した場合はマーカーを作らず、次回起動時に再試行する。旧名称と保存キーは `legacy_storage_migration.dart` の互換性定数にだけ残す。参照元の `kakutei_roller` からの移行は対象外。

AndroidのapplicationIdは `jp.nononoyuyuyu.open_campus_organizer`、iOSのBundle IDは `jp.nononoyuyuyu.openCampusOrganizer`。旧IDでインストールした検証版とは別アプリとして扱われ、設定・Token・履歴の自動移行は行わない。

Windows・Androidの外観変更は `AppearanceController` に注入した関数から [Platform Channel](https://docs.flutter.dev/platform-integration/platform-channels) を通してOS側へ伝える。iOS・Webはこの処理を行わない。runnerの `WindowAppearance` が5種類のICOリソースを切り替え、[WM_SETICON](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-seticon) で実行中ウィンドウの大小アイコンを更新する。起動時の保存配色も同じ経路で反映する。DPI変更時には再取得し、自分で作成したHICONだけを解放する。ネイティブ側の失敗は配色保存を妨げない。

アイコンは生成原画 `assets/branding/oco-master.png` を共通で使い、`tool/generate_icons.ps1` で `design/color_schemes.dart` の色から各OSの画像を再生成する。Windows専用の既存コマンド `tool/generate_windows_icons.ps1` も同じ変換へ委譲する。原画・変換手順は [アイコン](アイコン.md) を参照。

Windowsは `WM_SETICON` に加えて、ウィンドウのプロパティストアに `System.AppUserModel.RelaunchIconResource` を設定する。ウィンドウとインストーラーが作るショートカットのAppUserModelIDは `Nononoyuyuyu.OpenCampusOrganizer` に統一する。選択したICOのリソースIDを指定し、シェル再読み込み時にも再設定する。終了時はウィンドウのプロパティを解除する。起動前のEXE自体のアイコンは初期ダークとする。現在のEXEと起動先が一致するユーザーのショートカットだけ、アイコン・再起動アイコン参照・AppUserModelIDを更新し、SHChangeNotifyでExplorerへ通知する。表示中はITaskbarListのDeleteTab/AddTabでボタンを再登録する。スタートメニューは深さ4まで、デスクトップとピン留めは直下だけを調べ、ジャンクション等には入らない。AndroidはLauncherAppearanceがactivity-aliasを選び、MainActivity・共有エンジン・バックグラウンドサービスを無効化しない。API 33以降は一括切替、それ以前は新しい入口の有効化を先行する。

| 項目 | Windows | Android | iOS | ブラウザ |
| --- | --- | --- | --- | --- |
| 実Discord接続 | REST | REST | REST | 無効 |
| Token保存 | OS保護領域 | OS保護領域 | Keychain | 無効 |
| CSV書き出し | 保存ダイアログ | スマホは非表示、タブレットは共有 | スマホは非表示、タブレットは共有 | PC表示ではダウンロード |
| 操作履歴 | アプリ領域 | アプリ領域 | アプリ領域 | メモリのみ |
| サンプル | 利用可能 | 利用可能 | 利用可能 | 常にサンプル |

Androidはインターネット権限を宣言し、平文通信とバックアップを無効にする。iOSにはKeychain用entitlementsを設定する。署名鍵・配布証明書はリポジトリに含めない。iOSのビルド・署名にはmacOSとXcodeが必要。

Androidの暗号化保存ライブラリ11.0.0はcompileSdk 37を要求するため、[API 37.0をサポートするAGP 9.1.1とGradle 9.3.1](https://developer.android.com/build/releases/agp-9-1-0-release-notes)を使用する。Gradleの配布ZIPには公式のSHA-256を設定する。端末のSDKディレクトリを手動で書き換えて互換性問題を回避しない。

モバイルOSがアプリを停止する可能性があるため、大量操作をOSバックグラウンドで継続する保証はしない。未確認対象は履歴から確認する。
