# Open Campus Organizerの使い方

## 起動

開発環境はFlutter 3.44.4 / Dart 3.12.2です。Windowsの開発にはVisual StudioのC++ビルド環境、AndroidにはAndroid SDKとJava 17、iOSにはmacOSとXcodeを使用します。

```powershell
cd Source/OpenCampusOrganizer
flutter pub get --enforce-lockfile
flutter run -d windows
```

ツール一覧から「確定ロール」を開きます。PCではサイドバーからも直接開けます。まず画面を試す場合は「サンプルで試す」を選択してください。サンプルの操作は実際のDiscordに反映されず、端末の通常の操作履歴にも混在しません。

PCの「設定」は左下にあります。初期配色はダークです。「配色」から白・青、ウォームグレー、セージグリーン（淡い緑）、アプリコット（淡いオレンジ）にも切り替えられます。選択はすぐに反映され、ネイティブ版では次回起動時にも復元されます。既に保存した配色はそのまま引き継ぎます。画面や配色を切り替えても、入力中の抽出条件と接続は維持されます。

Windowsではウィンドウ・タスクバー・タスクトレイのアイコンが配色に連動します。同じEXEを起動する現在のユーザーのスタートメニュー・デスクトップ・タスクバーの既存ショートカットも更新します。EXE自体のアイコンはダークです。Androidのホーム画面アイコンも5配色に連動します。ホームアプリによって反映まで時間がかかったり、OSの「テーマアイコン」設定が色を上書きしたりする場合があります。iOSのホーム画面アイコンはダークです。

Discordの接続状態はPCのサイドバーでは「設定」の下、スマートフォンでは右上に表示します。接続済みは選択した配色のアクセント色、未接続は補助色、接続中とサンプルは注意色を使い、文字とアイコンも併用します。これはアプリの接続設定の状態で、常時ネットワーク疎通を監視する表示ではありません。

Androidでは画面上部のステータスバーと下部のシステムナビゲーション領域にも配色を反映します。アイコンはダークで白、明るい配色で暗くなるようOSへ指定します。ただし、検証したAndroid 15のエミュレーターでは、3ボタン操作のアイコン色がホームアプリ側で上書きされる現象が残っています。背景色とジェスチャー操作の明暗は確認済みです。詳細は [検証範囲](検証.md#032のスマートフォン表示の検証) を参照してください。iOSのホームインジケーター自体の表示はOSが管理します。

## Discord Botの準備

1. [Discord Developer Portal](https://discord.com/developers/applications) でApplicationとBotを作成します。
2. Botに「チャンネルを見る」「メッセージ履歴を読む」「ロールの管理」を許可してサーバーへ招待します。
3. サーバーのロール設定で、Botのロールを操作対象ロールより上へ移動します。
4. 本文や添付URLを取得する場合はMessage Content Intentを有効にします。ロールの一括解除にはServer Members Intentを有効にします。
5. アプリの「Discord接続」でBot Tokenを入力し、「接続する」を押します。必要な場合のみ「この端末にTokenを保存する」を選択します。

保存済みTokenは次回起動時に読み込んで接続します。保存済みTokenを削除しても、現在の接続は切断するまで維持されます。接続自体も終了する場合は「切断」を押してください。

保存済みTokenで接続すると、前回のサーバー・チャンネル・対象ロール、開始・終了日時、最小投稿数、Bot除外、本文・添付URLの選択も復元されます。サーバーを切り替えて戻ると、そのサーバーで前回選んだチャンネルとロールに戻ります。削除済み・閲覧不可の対象は選び直してください。サンプルや保存しない接続では、この設定を読み書きしません。

接続後は設定画面から、Botの招待URLをコピーできます。Tokenをチャット、文書、ソースコードに貼り付けないでください。

## 投稿者の抽出とロール付与

1. サーバー、通常のテキストチャンネル、対象ロールを選択します。一覧を更新するには抽出条件の更新ボタンを押します。
2. 開始日時の欄を押し、カレンダーと時刻選択で日本時間を指定します。終了日時も同じ方法で指定できます。終了日時の右端の「×」で空欄に戻せます。指定した終了分の投稿も含みます。開始・終了がともに09:00なら、09:00:00から09:00:59台までが対象です。終了日時が空欄の場合は抽出を開始した時刻までです。
3. 最小投稿数、Bot除外を指定します。PCでは本文・添付URLの取得も選べます。
4. 「権限をチェック」で必要権限を確認し、「対象者を確認」を押します。
5. 対象者一覧を確認します。同名でもDiscord IDごとに区別します。付与済みや退出済みのメンバーはスキップします。
6. 「ロールを付与」を押し、対象ロールと人数・対象者を確認して実行します。

入力条件を変更すると、結果を再確認する必要があります。操作プレビューから10分が経過した場合も、対象者の再確認が必要です。

画面が小さい場合だけ「条件設定」「対象者確認」「実行結果」のタブを表示します。大きいPC画面では条件と対象者を横に並べ、処理後の実行結果は右側の欄で切り替えます。

PCの対象者・投稿はページ式です。1ページの件数は画面の高さと文字サイズに合わせて変わります。ページ送りと実行ボタンは一覧の下にあり、画面を低くしてから戻しても先頭の対象者を保ちます。長い投稿は行を押すと全文を開けます。

スマートフォンの対象者一覧は名前と処理予定だけを表示し、一覧の中をスクロールします。検索と付与ボタンは画面内に残ります。横向きなど高さが小さい場合は検索と付与ボタンを同じ行に置き、下部のツールナビゲーションを隠します。左上からツール一覧へ戻れます。本文・添付URLの取得、投稿タブ、CSV出力はスマートフォンでは提供しません。以前の設定で本文取得を有効にしていても、スマートフォンでは取得しません。

PCの通知と進捗は画面下部の固定欄に表示します。スマートフォンでは画面を押し下げないポップアップを使います。通常の通知は6秒で消え、エラーは閉じるまで残ります。読み上げ利用時は通常の通知も自動で閉じません。長い通知は表示内でスクロールできます。処理中は通知内の「中止」が使えます。通知を押しても別のダイアログは開きません。

## ロールの一括解除

1. サーバーと対象ロールを選択し、ロール欄の直下にある「このロールを一括解除…」を押します。
2. 対象者一覧を確認します。投稿期間や投稿数の条件に関係なく、そのロールを持つ全メンバーを取得します。
3. 確認画面のチェックボックスにチェックを入れます。ロール名の入力は不要です。
4. 「一括解除する」を押します。

確認ダイアログの対象者一覧は、その欄内でスクロールして確認します。対象者が0人の場合は、PCでは下部通知欄、スマートフォンでは通知ポップアップに表示されます。

処理中にサーバーへ新たに加わった人や、確認後に新たにそのロールを得た人は、承認した対象一覧に含まれない限り操作しません。サーバーの変更が続く状況では、終了後にもう一度対象者を確認してください。

## CSVと操作履歴

PCでは、メンバータブの「CSV出力」は投稿者の集計、投稿タブの「CSV出力」は投稿一覧を出力します。投稿本文と添付URLは取得時に指定した場合にのみ含まれます。

Windowsでは保存ダイアログを使います。短辺600論理ピクセル以上のAndroid・iOSタブレットでは従来どおり共有メニューを使います。スマートフォンの画面には、操作履歴を含めCSV出力ボタンを表示しません。

ロール操作の結果はアプリ内に自動記録されます。「操作履歴」にはツール名、操作、対象、結果、日時が表示されます。操作を選ぶと、各メンバーの成功・スキップ・失敗・未処理・結果未確認を確認できます。履歴一覧は次のページへ進むと必要な分だけ読み込みます。

PC・タブレットでは履歴の「結果CSVを出力」からCSVを保存できます。設定の「結果CSVを自動保存」をオンにすると、以降の操作終了時にアプリの保存先へCSVも保存します。初期設定はオフです。オフに戻しても、過去の履歴やCSVは削除しません。0.4.0以前に作成したCSVもそのまま残ります。

広い画面では履歴一覧と詳細を左右に並べます。スマートフォンや小さいウィンドウでは「履歴」「詳細」で切り替えます。履歴一覧・対象者ごとの結果はどちらもページ式で、画面の高さと文字サイズに応じて1ページの件数が変わります。ウィンドウを縮めて戻しても、選択した操作と表示中の先頭の対象者を保ちます。長い失敗理由は結果欄内で全文を確認できます。

「中止」は未送信の操作を止めます。既に反映された変更は元に戻りません。通信切断や強制終了で結果が分からない場合は、履歴の「結果未確認」をDiscordで確認してください。

## 中断・再開とバックグラウンド処理

0.4.0以降は、抽出条件と承認したロール操作を実行前に保存します。通信が途切れると「接続復帰を待っています」と表示し、接続できるようになると自動で続けます。再起動後も未完了の処理を再開します。保存済みTokenがない場合は、承認時と同じBotで接続してください。

ロール操作は完了済みの人を再操作せず、送信結果が不明な人はDiscord側のロールを確認してから続けます。対象者を勝手に追加しません。抽出は同じ期間を再取得し、結果を確認するまでロールを操作しません。「中止」した処理は次回起動時に再開しません。権限や認証のエラーで止まった場合は原因を解消し、設定に再開待ちの表示があれば「再開」を押してください。不要な処理は「取り消す」で破棄します。

Windowsでは、設定の「閉じてもタスクトレイで続ける」が初期オフです。閉じるボタンを押すと確認画面が出て、終了を選ぶと進行中の応答と保存を待って終了します。オンにすると閉じるボタンで通知領域へ入り、処理を続けます。トレイアイコンを押すと画面を戻せます。右クリックの「終了」から終了する場合も確認します。Windows起動時の自動起動はありません。

Androidでは処理中の通知から進捗確認・中止・画面への復帰ができます。初回の処理時に通知の許可を求めます。「完了後にアプリを終了」は初期オンです。ホームへ戻るなどしてバックグラウンドにした状態で最後のロール操作が完了すると、結果通知を残して画面と処理エンジンを終了します。前面にいる場合や対象者の抽出後には終了しません。設定をオフにすると完了後も画面を保持します。

iOSはOSが許可した時間内で処理を続けます。iOS 26以降は長時間の継続処理も使用しますが、OSが終了を要求した場合は保存して止め、画面へ戻った際に再開します。処理完了時はバックグラウンド実行を終了し、アプリのプロセス管理をOSへ返します。強制終了の設定は表示しません。

Androidの長時間実行にもOSの上限があります。通知や省電力の設定によって表示・継続時間が変わり、OSの強制停止や電源断まで継続できる保証はありません。未完了の保存記録は次回起動時に使用します。0.3.x以前の未完了履歴は自動再開しません。

## ビルドと検証

正式名称はOpen Campus Organizer、略称はOCOです。0.3.0からソース・文書・テストのフォルダも `OpenCampusOrganizer` に統一しています。

Windowsでは旧版の設定・操作履歴・保存済みTokenを初回起動時に引き継ぎます。旧版のデータは残し、新名称側に既にあるデータは上書きしません。0.4.0以降のインストーラーで「データを削除して新しく始める」を選んだ場合は引き継ぎません。導入・削除時の選択は [配布手順](配布.md) を参照してください。Android・iOSではアプリ識別子も変更したため、旧IDの検証版とは別アプリとなり、設定とTokenは再入力が必要です。

`Source/OpenCampusOrganizer` で実行します。

```powershell
flutter analyze
flutter test ../../Tests/OpenCampusOrganizer
flutter build windows --release
flutter build apk --debug
```

Windows版は `build/windows/x64/runner/Release/` のフォルダ全体が必要です。EXEだけを移動しないでください。ビルド済みZIPを使う場合も、フォルダ全体を展開して `open_campus_organizer.exe` を起動します。

GitHub Releasesで配布するWindowsインストーラーにはVC++のx64再頒布可能パッケージを同梱しています。不足している場合は自動で導入します。自分でビルドしたフォルダを直接コピーする場合は、別途ランタイムが必要になることがあります。

Androidの検証用APKは `build/app/outputs/flutter-apk/app-debug.apk` に生成されます。GitHub Releasesには専用の配布鍵で署名したRelease APKを公開します。インストール方法と配布物の再作成は [配布手順](配布.md) を参照してください。

Androidの対応範囲はAndroid 7.0（API 24）以降です。ビルドにはAndroid SDK Platform 37、Java 17、Gradle 9.3.1を使います。端末のSDKの場所は `android/local.properties` で指定し、この端末固有ファイルはGitに含めません。

iOSはmacOS上で実行します。アプリ内の対応設定はiOS 15以降です。

```sh
flutter build ios --simulator --no-codesign
```

ブラウザのサンプルは次で起動します。実Bot接続は提供しません。

```powershell
flutter run -d chrome
```

## 主な対処

| 状態 | 対処 |
| --- | --- |
| 接続できない | Token、ネットワーク、Botの参加状態を確認する |
| 本文や添付が取得できない | Message Content Intentを有効にして再接続する |
| 一括解除のメンバーを取得できない | Server Members Intentを有効にして再接続する |
| ロールが操作不可 | Botの権限とロールの上下関係を確認する |
| 履歴を読めない・保存できない | アプリの保存領域を保管し、空き容量・アクセス権を確認する |
| 投稿が100,000件を超える | 期間を分割して抽出する |
| 一括解除の走査対象が100,000人を超える | この規模のサーバーの一括解除には対応していない |
| Discordの利用制限 | 表示された停止状態を確認し、時間をおいて対象者から再確認する |

削除済みの投稿や、Botから見えないチャンネルの投稿は取得できません。
