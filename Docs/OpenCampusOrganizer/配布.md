# Open Campus Organizerの配布

## ダウンロードとインストール

[GitHub Releases](https://github.com/nononoyuyuyu/OC_tools/releases/latest) から端末に合うファイルを取得します。

| ファイル | 用途 |
| --- | --- |
| `OpenCampusOrganizer-<version>-windows-x64-setup.exe` | Windows 10 バージョン2004以降・Windows 11の64ビット環境向けインストーラー |
| `OpenCampusOrganizer-<version>-android.apk` | Android 7.0（API 24）以降向け。arm64-v8a・armeabi-v7a・x86_64を含む共通APK |
| `OpenCampusOrganizer-<version>-android-arm64-v8a.apk` | arm64-v8aのAndroid端末向けAPK |
| `OpenCampusOrganizer-<version>-android-armeabi-v7a.apk` | armeabi-v7aのAndroid端末向けAPK |
| `OpenCampusOrganizer-<version>-android-x86_64.apk` | x86_64のAndroid端末・エミュレーター向けAPK |
| `SHA256SUMS.txt` | 配布ファイルのSHA-256 |

CPU別APKは対応する端末向けのライブラリだけを含むため、共通APKより小さくなります。端末のCPUが分からない場合は共通APKを選んでください。インストールするAPKは1つです。

GitHubで配布する共通APKとCPU別APKは、同じアプリID・署名鍵・ビルド番号を使用します。対応するCPUであれば、どちらの形式からでも次の配布版へ更新できます。CPU別APKのビルド番号はFlutter標準のCPU別加算を適用せず、`pubspec.yaml` に合わせて検証します。Google Playへ複数APKを登録する場合とは配布方針が異なります。

Windowsはインストーラーを実行します。標準の導入先は現在のユーザーの `%LOCALAPPDATA%\Programs\OpenCampusOrganizer` です。新規導入・更新ともに保存先の選択画面を表示します。スタートメニューは登録するフォルダーを選択でき、登録しない選択もできます。デスクトップのショートカットも任意です。Flutterの実行ファイル・DLL・データと、Microsoft署名済みのVC++ x64ランタイムを同梱しているため、導入時のダウンロードは不要です。Discordの利用にはインターネット接続が必要です。

VC++ランタイムが同梱版以上なら導入を省略します。不足している場合のみ管理者権限で自動導入するため、Windowsのユーザーアカウント制御で許可してください。導入に失敗した場合はアプリのインストールを停止します。再起動が必要な場合は案内を表示し、アプリを自動起動しません。

指定先に同じアプリがある場合は、同じAppIdのアンインストール記録を継続して本体を更新します。既に登録済みなら前回の保存先が初期表示され、確認画面にも更新であることを表示します。別フォルダーへ移す場合は、設定・履歴を残して既存のアプリをアンインストールしてから新しい保存先へ導入してください。二重導入で古いアンインストール登録を失わないよう、登録済みの別保存先への上書きは拒否します。0.4.0以降は保存済みデータを検出すると「前回のデータを引き継ぐ」（初期選択）と「データを削除して新しく始める」を選べます。インストールが成功した後で初期化するため、途中でキャンセルした場合はデータを変更しません。

Windowsの「インストールされているアプリ」から削除すると、設定・履歴を残すか確認します。「はい」は保持、「いいえ」は削除、「キャンセル」はアンインストール中止です。対象は現在のWindowsユーザーの配色・接続先・抽出条件・操作履歴・自動保存CSV・保存済みToken・再開待ちの処理です。旧名称の保存先も含め、削除したデータを次回起動で再取り込みしません。保持した未完了タスクは、再インストール後の起動で再開対象になります。共有VC++ランタイム、配布用署名鍵、利用者が別名で作成したファイルは削除しません。他のWindowsユーザーのデータは対象外です。

配布するOCOのEXEとインストーラーにはAuthenticode署名がないため、Windowsが発行元不明の案内を表示する場合があります。同梱ランタイムのMicrosoft署名とは別です。

AndroidはAPKを端末に保存して開き、使用したブラウザやファイルアプリからのインストールをOSの画面で許可します。以後のAPKも同じ配布鍵で署名し、上書き更新します。同じアプリIDのDebug版は署名が異なるため、そのまま更新できません。その場合は必要な情報を控えて検証版をアンインストールしてから導入します。アンインストールするとAndroid側の設定は失われます。

## 開発環境

共通環境はFlutter 3.44.4 / Dart 3.12.2です。以下のPowerShellスクリプトはPowerShell 7以降で実行します。

- Windows: Visual StudioのC++デスクトップ開発環境、Windows SDK、Inno Setup 7.1.0。
- Android: Android SDK Platform 37、Build Tools、Java 17。Gradle 9.3.1はプロジェクトのWrapperを使用します。Android Studioに同梱されたJavaも使用できます。

`flutter doctor -v` で環境を確認してください。開発用SDKやAndroid Studioを利用者のPCに入れる必要はありません。

## Windowsインストーラーの作成

[Inno Setup公式ダウンロード](https://jrsoftware.org/isdl.php) から7.1.0の64ビット版を導入します。[公式の検証方法](https://jrsoftware.org/isdl-verify.php) に従って配布元を確認してください。

`Source/OpenCampusOrganizer` から実行します。

```powershell
pwsh -File tool/build_windows_installer.ps1
```

Flutter依存関係の固定確認、Releaseビルド、VC++パッケージのハッシュとMicrosoft署名の検証、使用MSVCに対するランタイムのバージョン確認、インストーラーの作成を行います。出力先はリポジトリの `artifacts/release/<version>/` です。`-CompilerPath`、`-OutputDirectory`、`-DependencyCache` でパスを指定できます。

ランタイムの固定URL・バージョン・SHA-256は [dependencies.json](../../Source/OpenCampusOrganizer/installer/windows/dependencies.json) にあります。0.3.1は14.51.36247.0を同梱します。更新時は公式パッケージを取得して署名を検証し、3項目を同時に更新します。[Microsoftの案内](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) に従い、ビルドに使うMSVCと同じか新しいランタイムが必要です。

標準はユーザー単位の導入です。管理用途では `/ALLUSERS` で全ユーザー向け、`/CURRENTUSER` でユーザー単位を明示できます。更新では既存のインストール対象と揃えてください。両方の登録領域（HKCU・HKLM）を確認し、対象をまたぐ二重導入は同じ保存先でも拒否します。対象を変更する場合は既存のアプリを削除してから導入します。サイレント導入は `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` を指定します。サイレント時はアプリを起動しません。ランタイムが不足している非管理者環境ではUACの許可が必要です。

サイレント実行時はデータ保持が既定です。初期化を明示する場合はインストーラーへ `/DATA=reset`、削除を明示する場合はアンインストーラーへ `/DATA=delete` を渡します。いずれも対象は実行中のWindowsユーザーです。初期化が失敗するとインストーラーは終了コード20を返し、アプリを自動起動しません。保存先がジャンクションやシンボリックリンクになっている場合は、そのリンク先を削除せずエラーにします。

データ削除のテストには `-UserDataTestRoot` を指定した専用ビルドを使用します。この値はリポジトリの `artifacts` 配下に限定し、出力名も `OpenCampusOrganizer-userdata-test-setup.exe` に変わります。専用ビルドはReleaseへ添付しません。具体的な検証は [テスト手順](../../Tests/OpenCampusOrganizer/README.md) を参照してください。

## Android Release APKの作成

Windowsでの初回のみ、次を実行します。

```powershell
pwsh -File tool/build_android_release.ps1 -InitializeSigning
```

RSA 4096ビットの専用署名鍵をリポジトリ外の `%LOCALAPPDATA%\OpenCampusOrganizer\Signing` に作成します。鍵の別名は `open-campus-organizer` です。パスワードはランダムに作成し、WindowsユーザーのDPAPIで暗号化して `android-release.password.dpapi` に保存します。秘密鍵は `android-release.jks` です。スクリプトはパスワードを出力せず、ビルド中のプロセス環境変数にだけ渡し、終了時に元の環境へ戻します。ファイルが片方だけの場合は自動再生成しません。

2回目以降は既存の署名鍵を使います。

```powershell
pwsh -File tool/build_android_release.ps1
```

`-JavaHome`、`-AndroidSdk`、`-SigningDirectory`、`-OutputDirectory` で環境に合わせたパスを指定できます。スクリプトはReleaseビルド後に `apksigner verify` とDebug属性の検査を実行し、`artifacts/release/<version>/OpenCampusOrganizer-<version>-android.apk` にコピーします。署名情報がないReleaseビルドは失敗し、Debug鍵へ切り替えません。Debugビルドにはこの配布鍵を使いません。

CPU別APKも作成する場合は、同じソースと署名鍵で次を実行します。

```powershell
pwsh -File tool/build_android_release.ps1 -SplitPerAbi
```

`arm64-v8a`・`armeabi-v7a`・`x86_64` の3ファイルを生成します。全ファイルの存在・署名・Debug属性を検証した後、CPU名を含むファイル名で同じ配布先へコピーします。共通APKとCPU別APKを両方配布する場合は、通常のコマンドとこのコマンドを実行し、各ファイルのSHA-256を配布一覧に含めてください。

**更新のために同じ署名鍵を保管してください。** JKSと暗号化パスワードはGit・Release・共有ログに含めません。DPAPIファイルは元のWindowsユーザーと環境に結び付いており、ファイルを別PCへコピーするだけではパスワードを復元できません。PC移行前に元の環境で鍵とパスワードを安全なバックアップへ移し、新環境用の保管方法を準備してください。元の鍵を失うと既存APKへの上書き更新ができなくなります。

他のOS・CIで配布鍵を管理する場合、Gradleは `OCO_ANDROID_STORE_FILE`、`OCO_ANDROID_STORE_PASSWORD`、`OCO_ANDROID_KEY_ALIAS` をプロセス環境から受け取ります。秘密情報をコマンド行、文書、Git管理ファイルへ記載しないでください。リポジトリのCIは配布鍵を使用せずDebug APKを検証します。

署名方式とAndroid配布の詳細は [Flutter公式手順](https://docs.flutter.dev/deployment/android) を参照してください。アプリIDは `jp.nononoyuyuyu.open_campus_organizer` です。0.3.1の公開証明書SHA-256は次の値です。

```text
067f21d198dacdbea0f618e89a09a1b61ac7bccfe0917604daced28222ac12e2
```

## GitHub Releaseの作成

文書・ソース・テストの変更を日本語のPRで確認し、マージしたコミットを対象に両方を作成します。`pubspec.yaml` のバージョンとビルド番号、設定画面、DiscordのUser-Agentを合わせて更新してください。両OSの成果物を作成した後にSHA-256を計算し、Releaseの `SHA256SUMS.txt` と照合できるようにします。

タグは `v0.3.1` のように付けます。Release本文に対象OS、導入方法、検証範囲、Windows署名の有無を記載し、インストーラー・APK・SHA256SUMS.txtを添付します。秘密鍵、DPAPIファイル、実Token、端末固有の設定は添付しません。公開前に添付ファイルを取得してローカルのハッシュと一致することを確認します。

iOSはmacOS・XcodeとApple側の署名設定が必要です。このReleaseにはiOS用配布物を含めません。
