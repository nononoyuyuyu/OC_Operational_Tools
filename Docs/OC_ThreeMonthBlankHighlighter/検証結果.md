# OC_ThreeMonthBlankHighlighter v2.1 検証結果

実施日: 2026年9月11日

## レビュー結果

2.0では専用の条件付き書式、現在継続中の末尾区間、安全な解除・復元を実装した。2.1では利用者の3例に従い、登録翌月から先月末までの完了月数と、当月の記入確認を分離した。書式更新、フィルタ非操作、権限は変更しない。

「1か月前まで」は9/11なら8/31までと定義する。9月の空欄は月数に含めないが、9/13など当月の未来日への記入も除外条件に含める。10月以降は含めない。日付列のない月は空欄と推測せず連続期間を中断する。

## 実施済みローカル検証

```bash
node --test Tests/OC_ThreeMonthBlankHighlighter/*.test.js
```

Node.js v22.16.0で72テスト成功、失敗0、スキップ0。34件のロジック試験、34件の統合モック試験、4件の安全性試験。2.0時点の55件を基に月単位の期待値へ更新し、安全性・復元テストは維持した。

| 9/11実行時の再現条件 | 結果 |
| --- | --- |
| 4/5登録、5～9月空欄 | 5～8月の4か月、対象 |
| 6/1登録、7～9月空欄 | 7～8月の2か月、対象外 |
| 4/5登録、5～8月空欄、9月記入 | 当月記入あり、対象外 |

4,096通りの記入パターンと欠落月込み729通りを別実装の順方向オラクルと照合した。上限試験は学生1,000人×日付300列を実際に配列生成して全件判定した。月替わり・タイムゾーン、当月未来日の確認中変更、再実行時の専用赤表示解除も検証した。ローカル性能をGASの処理時間として扱わない。

## 未実施・限界

実際のGoogle スプレッドシートへの導入、Google側の条件付き書式の表示・優先順位、保護設定、Chrome/Safariでのダイアログはこの環境では検証していない。モック成功を実機成功として報告しない。

手動受け入れ手順: 3例の学生行を作成し、確認専用関数で1例目だけが対象になることを確認する。元背景色が黄色の登録日セルを赤表示にし、当月の日付へ値を入れて再実行し黄色へ戻ることを確認する。他の条件付き書式がある場合も対象外後に再適用されることを確認する。旧版で直接塗った赤は自動復元できない。

人の同時編集はDocumentLockで停止できない。実行中は対象データと条件付き書式の共同編集を避ける。
