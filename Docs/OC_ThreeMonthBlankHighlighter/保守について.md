# OC_ThreeMonthBlankHighlighter 保守について

版2.0／2026年9月11日

## 構成

`Core.gs`の`ocBlank3mV2Core_()`が純粋関数群を返す。`Code.gs`はGAS接続層。公開関数は実行と確認専用の2つ。既存抽出ツールの関数を呼ばず、グローバル変数を作らない。

設定は`ocBlank3mV2Config_()`に集約する。対象シート、3暦月、上限、赤色、専用数式が含まれる。数式マーカーはルールの所有識別子なので安易に変更しない。変更する場合は旧専用ルールの移行方法も実装する。

## 維持する不変条件

- 未来列を判定せず、最新の対象日付列まで続く末尾区間だけを評価する。
- 過去区間の達成で走査を打ち切らない。
- Dateの年月日はスプレッドシートのタイムゾーンで解釈する。
- 月末は丸め、90日換算しない。
- 日付らしい壊れたヘッダーを黙って捨てない。
- 全該当者が対象外になった場合も専用ルールを削除する。
- 元背景色・フィルタ・行表示・セル値・他ルールの相対順を変更しない。
- 手作業や旧版の直接背景色を推定して解除しない。
- ロックの外で確認し、ロック取得後に再読取、解放後に結果表示する。
- 復元は現在ルールが自分の書込内容と一致する場合だけ行う。
- 氏名、学籍番号、セルの生値をログ・メッセージ・数式へ載せない。

## 競合と書式

`setConditionalFormatRules()`はシートのルール一覧を置換する。そのため、他ルールを同じオブジェクトのまま保存し、条件・引数・範囲・RGB/テーマ色・文字装飾・グラデーション・優先順の署名を比較する。未知のルールを解析できないときは安全側に停止する。

確認中と権限確認中の変更を検出するが、GASのDocumentLockは人や別プロジェクトの編集を止めない。読取りと書込みの隙間の完全な排他性は保証しない。運用では実行中の共同編集を避ける。

専用ルールは静的な判定結果のセル範囲である。背景表示だけで最新状態を断定せず、編集後に再実行する。

## テストとCI

新ツールだけのローカル検証:

```bash
node --test Tests/OC_ThreeMonthBlankHighlighter/*.test.js
```

既存ツールとの共存を含む検証:

```bash
node --test Tests/OC_KakuteiExtractor/*.test.js
```

後者は既存必須チェックで使用されているコマンド。`three-month-integration.test.js`から新ツールの全テストと両GASの結合読込を実行する。ワークフロー名を変えず、新GASが必須CIから漏れないようにする。既存テストを減らしたり、別テストへ置き換えたりしない。

主な試験: 4,096通りの末尾パターン、暦月境界、登録日、タイムゾーン、日付列並び替え、1,000人・300日付列、対象外への復帰、該当0件、冪等性、保護・結合セル、競合、書込み前後の障害、復元失敗、ログ・外部通信の禁止。

## 配布・移行

リポジトリ変更は日本語コミットとPRを用いる。必須の`OCO検証`、`GASの単体・統合・安全性テスト`が最新mainに対して成功した後、Squashでマージする。GitHubマージは利用者のApps Scriptへ自動反映しない。

新規導入は2ファイル。旧7ファイル版を置換する際は、他GASと取り違えないよう公開関数と`ocBlank3m`プレフィックスを確認する。既存プロジェクトのマニフェストを丸ごと上書きしない。

元に戻すときは専用ルールを削除し、保存していたスクリプト版へ戻す。旧版へ戻すと直接背景色を書き換えるので、利用者へ相違を説明する。
