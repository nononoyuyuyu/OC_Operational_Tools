# OC_ThreeMonthBlankHighlighter 保守について

版2.1／2026年9月11日

## 構成

`Core.gs`の`ocBlank3mV2Core_()`が純粋関数群を返す。`Code.gs`はGAS接続層。公開関数は実行と確認専用の2つ。既存抽出ツールの関数を呼ばず、グローバル変数を作らない。

設定は`ocBlank3mV2Config_()`に集約する。対象シート、必要な完了月数3、版、上限、赤色、専用数式が含まれる。数式マーカーはルールの所有識別子なので安易に変更しない。変更する場合は旧専用ルールの移行方法も実装する。2.1ではマーカーを維持し、CoreとCodeの版が一致しなければ停止する。

## 維持する不変条件

- 登録月を数えず、翌月から先月までの末尾の連続空欄月を評価する。
- 当月は空欄月数に含めない。当月内の未来日も含め、記入があれば対象外とする。翌月以降は対象外。
- 月内に1件でも非空欄があれば、その月で連続期間を中断する。
- 日付列のない月を空欄と推測しない。過去区間の達成で走査を打ち切らない。
- Dateの年月日はスプレッドシートのタイムゾーンで解釈する。
- 年月番号で完了月を数え、90日換算や登録日と同じ日付の月加算で判定しない。
- 日付らしい壊れたヘッダーを黙って捨てない。
- 全該当者が対象外になった場合も専用ルールを削除する。
- 元背景色・フィルタ・行表示・セル値・他ルールの相対順を変更しない。
- 手作業や旧版の直接背景色を推定して解除しない。
- ロックの外で確認し、ロック取得後に再読取、解放後に結果表示する。
- 復元は現在ルールが自分の書込内容と一致する場合だけ行う。
- 氏名、学籍番号、セルの生値をログ・メッセージ・数式へ載せない。

`windowFor`が先月末・当月末、`completedMonths`が月別の空欄判定と当月記入、`trailing`が3か月閾値を担当する。`analyze`の署名には当月の未来日も含める。書式設定・解除は変更しない。

## 競合と書式

`setConditionalFormatRules()`はシートのルール一覧を置換する。そのため、他ルールを同じオブジェクトのまま保存し、条件・引数・範囲・RGB/テーマ色・文字装飾・グラデーション・優先順の署名を比較する。未知のルールを解析できないときは安全側に停止する。

確認中と権限確認中の変更を検出するが、GASのDocumentLockは人や別プロジェクトの編集を止めない。読取りと書込みの隙間の完全な排他性は保証しない。運用では実行中の共同編集を避ける。

専用ルールは静的な判定結果のセル範囲である。背景表示だけで最新状態を断定せず、編集後・月替わりに再実行する。

## テストとCI

新ツールだけのローカル検証:

```bash
node --test Tests/OC_ThreeMonthBlankHighlighter/*.test.js
```

既存ツールとの共存を含む検証:

```bash
node --test Tests/OC_KakuteiExtractor/*.test.js
```

後者は既存必須チェックで使用されているコマンド。`three-month-integration.test.js`から新ツールの全テストと両GASの結合読込を実行する。ワークフロー名を変えず、新GASが必須CIから漏れないようにする。既存の安全性・書式更新テストを減らさない。

主な試験: 利用者の3例、4,096通りの月別記入パターン、欠落月込み729通り、月末・年越し・当月未来日の記入、登録日、タイムゾーン、列順、1,000人・300日付列、対象外への復帰、該当0件、冪等性、保護・結合、競合、書込み前後の障害、復元失敗、版混在、ログ・外部通信の禁止。

## 配布・移行

リポジトリ変更は日本語コミットとPRを用いる。必須の`OCO検証`、`GASの単体・統合・安全性テスト`が最新mainに対して成功した後、Squashでマージする。GitHubマージは利用者のApps Scriptへ自動反映しない。

新規導入は2ファイル。旧7ファイル版を置換する際は、他GASと取り違えないよう公開関数と`ocBlank3m`プレフィックスを確認する。2.0から2.1への更新でも2ファイルを両方置換する。既存プロジェクトのマニフェストを丸ごと上書きしない。

元に戻すときは専用ルールを削除し、保存していたスクリプト版へ戻す。試作版へ戻すと直接背景色を書き換え、2.0へ戻すと経過期間判定に戻るので、利用者へ相違を説明する。
