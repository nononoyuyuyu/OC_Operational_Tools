# OC_ThreeMonthBlankHighlighter 使い方・導入方法

版2.1／2026年9月11日／対象: デスクトップ版Chrome・macOS版Safari

## 1. 導入するファイル

現リポジトリは`nononoyuyuyu/OC_Operational_Tools`。`Source/OC_ThreeMonthBlankHighlighter/`から次の2ファイルを使用する。

| リポジトリ上のファイル | Apps Script上の推奨名 |
| --- | --- |
| `Core.gs` | `OC_ThreeMonthBlankHighlighter_Core` |
| `Code.gs` | `OC_ThreeMonthBlankHighlighter` |

対象スプレッドシートの「拡張機能 → Apps Script」から開いたバインドプロジェクトへ登録する。既存の`OC_KakuteiExtractor`は削除・変更しない。

2.0からの更新でも2ファイルを両方とも全文置換する。関数名と条件付き書式の専用マーカーは変更しないため、ボタンの再設定や既存専用ルールの手動削除は不要。片方だけを更新して版が異なる場合は書き込まず停止する。

## 2. 試作版から移行する場合

旧版の空欄判定ツール用7ファイルは、取り違え防止のためバックアップしてから削除する。対象は旧ツールのCode、Analysis、Headers、BlankLogic、Highlight、DateUtils、Messages相当のファイルであり、既存抽出ツールの同名ファイルではない。混在する業務コードがある場合はファイル全体を削除せず、旧`ocBlank3m`関数と旧公開関数だけを取り除く。

その後、上表の2ファイルを登録する。`function runOC_ThreeMonthBlankHighlighter`の定義が1つだけあることを確認する。今後の更新ではこの2ファイルを全文置換し、別ファイルへ重複追加しない。

旧版で直接塗りつぶした赤色は、自動では解除されない。新版の専用表示が解除されても、その下にある旧版の赤色は見える。以前の元色が分かるセルだけを必要に応じて手動復元する。登録日列全体を一括で白へ変更しない。

## 3. 権限と実行

単独導入では同フォルダの`appsscript.json`を使用する。既存プロジェクトと統合する場合は既存マニフェストを上書きせず、`script.container.ui`と`spreadsheets.currentonly`が含まれることを確認する。初回のみ権限を承認する。2.1ではマニフェストの変更はない。

最初は次をApps Scriptエディタから実行し、書き込まずに対象を確認する。

```text
previewOC_ThreeMonthBlankHighlighter
```

本実行の関数は次のとおり。`スクリプト用シート`等の図形・画像ボタンへ括弧なしで割り当てる。旧版と同じ関数名である。

```text
runOC_ThreeMonthBlankHighlighter
```

GASの初回承認後にボタンを再実行する。モバイル版のボタン操作は受け入れ対象外。

## 4. 判定の読み方

登録月を数えず、翌月から先月末までに連続3か月以上、各月の日付セルが全て空欄の行を対象にする。当月は月数に加えないが、当月の日付セルに記入があれば対象外にする。当月内の未来日も記入確認には含め、翌月以降の予定は無視する。

9月11日実行の場合、集計は8月31日まで、記入確認は9月30日まで。

| 登録日 | 状態 | 結果 |
| --- | --- | --- |
| 4/5 | 5～9月空欄 | 5・6・7・8月の4か月で対象 |
| 6/1 | 7～9月空欄 | 7・8月の2か月なので対象外 |
| 4/5 | 5～8月空欄、9月に記入 | 当月記入ありで対象外 |

月の中に1つでも非空欄があれば、その月で連続期間をリセットする。次の月から先月まで再び3か月以上空欄が続き、当月にも記入がなければ対象になる。日付列が存在しない月は空欄と断定せず、連続期間を中断する。最終日付列が8/30でも8月中の全セルが空欄なら、9月実行時には8月を1か月と数える。

空文字・空白だけ・ゼロ幅文字だけを空欄とする。〇、○、×、確定、キャンセル、定員、その他の非空文字は全て区間を中断する。登録日列「登録・更新日」の現在値を使用するため、更新日時への変更は集計開始月にも影響する。

## 5. 確認画面と赤表示の更新

画面には基準日、ヘッダー行、先月末の集計終点、当月末の記入確認終点、対象件数、登録日セル番地、連続区間と月数を表示する。氏名・学籍番号は表示しない。判定保留の登録日は理由とセル番地を表示する。

「はい」で専用の条件付き書式を更新する。「いいえ」または閉じる場合は変更しない。対象が0件でも実行すれば、以前の専用赤表示を解除できる。再実行で当月の日付に記入が入った行は対象外となり、新版が管理する赤表示だけが外れる。

元の背景色、手作業の色、他の条件付き書式は保持される。専用ルールは最上位となり、対象セルの赤表示を優先する。解除後は元の色や既存ルールの表示に戻る。確認付きの実行時更新なので、セル編集や並べ替えの直後、および月替わりには再実行する。

## 6. 主なエラー

- 日付見出しを確定できない: `4/19`が文字列だけになっていないか確認する。日付型または`2026/4/19`のような年付き値にする。
- 必須ヘッダーを特定できない: 登録日列と学籍番号が同一行に各1つあるか確認する。
- 保護セル・結合セル: 指定セルの権限と結合状態を確認する。ツールは保護を解除しない。
- 確認中に変更: 日付・データ・条件付き書式に変更があった。もう一度確認から実行する。当月内の未来日への記入も確認対象。
- 版が異なる: `Core.gs`と`Code.gs`の両方を2.1へ更新する。
- 復元を確認できない: 他の利用者の変更を消さないよう、現在の条件付き書式を管理者と確認する。再実行を繰り返さない。

## 7. 停止・ロールバック

「表示形式 → 条件付き書式」で次の式に完全一致する専用ルールだけを削除すると、新版の赤表示を一括で外せる。他ルールは削除しない。

```text
=N("OC_ThreeMonthBlankHighlighter:v2")=0
```

スクリプトファイルを削除するだけでは条件付き書式は残る。ツールを廃止する場合は先に専用ルールを削除する。
