# OC_KakuteiExtractor テスト

## 1. 実行環境

- Node.js 18以降
- 外部npmパッケージ不要

## 2. 実行方法

```bash
node Tests/OC_KakuteiExtractor/logic.test.js
node Tests/OC_KakuteiExtractor/workflow.test.js
node Tests/OC_KakuteiExtractor/view-reset.test.js
node Tests/OC_KakuteiExtractor/static.test.js
node --test Tests/OC_KakuteiExtractor/*.test.js
```

## 3. テスト範囲

### `logic.test.js`

- 日付解析と3年間上限
- 必須列と任意行ヘッダー
- 内部Date型の日付見出し
- 追加列の無視
- `SA/TA`と日付セルの空欄
- 留学生名用フリガナ
- 学生1,000人、日付300列

### `workflow.test.js`

- 抽出からコピー確認までの統合フロー
- フィルタ本体を保持し、条件だけ解除
- 手動非表示行を条件解除より先に再表示
- 行グループAPIを呼び出さないこと
- 行再表示失敗時の条件維持
- シート保護時の無変更
- 条件解除失敗時の復元
- 確認中のデータ変更検出

### `view-reset.test.js`

- フィルタ条件の退避
- 絶対列番号による条件解除
- `Filter.remove()`の不使用
- 通常フィルタなし
- 手動非表示行の再表示
- 行グループ展開・折りたたみAPIの不使用
- 行グループAPIが例外を投げるモックでも正常処理
- 条件解除失敗時の復元
- 復元失敗時の警告
- 保護状態確認失敗時の無変更

### `static.test.js`

- GASとHTMLの構文
- トップレベル字句宣言なし
- フィルタ本体削除APIの不使用
- 条件解除・退避・復元APIの存在
- 行グループAPIの不使用
- 手動非表示行の再表示と条件解除の実装順序
- 外部通信・ログ・永続保存APIの不使用
- 最小OAuthスコープ

## 4. 期待される出力

`memory.test.js` は元マトリクスをオフセットで参照した場合の出力・旧形式の指紋JSON・エラーの実セル位置を検証します。1,000学生×300日付列と50万セル上限の入力も含みます。`benchmark.js` は旧ソースと現ソースを別のNodeプロセスで比較する測定用で、自動テストとは別です。実行方法・測定値は [GAS性能検証](../../Docs/OC_KakuteiExtractor/性能検証-20260908.md) を参照してください。

```text
単体検証: PASS（抽出・許容文字・最大構成 ... ms）
統合モック検証: PASS（行グループ非操作・フィルタ本体保持）
表示状態検証: PASS（行グループ非操作・フィルタ本体保持）
静的・セキュリティ検証: PASS（行グループ非操作・フィルタ本体保持）
```

## 5. 実機でのみ確認できる項目

- フィルタボタンとフィルタ範囲が実行後も残ること
- Google スプレッドシート上の各種フィルタ条件の退避・復元
- シート保護時の実際の権限エラー
- 手動非表示行が再表示されること
- 行グループの開閉状態が実行前後で変化しないこと
- 行グループが存在しないシートでエラーにならないこと
- 折りたたまれた行グループ内のデータもコピーされること
- 保存済みフィルタ表示の非変更
- Chrome・Safariのクリップボード処理
